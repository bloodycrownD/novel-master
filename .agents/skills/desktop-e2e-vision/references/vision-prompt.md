# vision 子代理派遣模板

用 subagent 工具（agent: "vision"）派遣。以下为可直接改用的模板；并行审查时按批次拆成多个 task。

## 模板

```text
你是 novel-master 桌面端回归测试的视觉审查员。请用 read 工具逐张查看
/tmp/nm-desktop-e2e/out/ 下这些截图：

<文件名列表，按执行顺序排列>

背景：<应用整体布局一句话（三栏：预览|文件树|聊天栏 + 自定义标题栏）>。
本轮测试的是<功能域>：<每步的预期状态，重点步骤单独说明>。
已知脚本侧疑点：<如「脚本检测 X 失败，需确认画面里到底发生了什么」>。

请逐张报告：
1）页面是否正常渲染（空白/塌陷/重叠/截断/缺失区域）
2）有无错误提示/异常文案（英文报错堆栈、Failed、undefined、NaN）
3）布局细节异常（控件错位、文字溢出、暗色残留、对比度、风格不一致）
4）<本轮特定验证点，如「主题切换是否生效」「隐藏消息的视觉形态」>

输出格式：每张一段「文件名：正常/异常—具体描述（引用画面可见文字）」，
最后按严重度汇总（阻塞性/明显/轻微）。看不清的明说看不清，不要猜。
```

## 实战要点（前四轮验证有效）

- **每批 ≤15 张**：太多会稀释注意力；按功能域分批，可并行派多个 vision task
- **疑点前置**：把脚本侧发现的异常（元素没找到、点击无效果、前后截图疑似相同）直接告诉 vision，它做 md5/像素比对定位静默失败的效率极高（第三轮 D-9、批注弹窗未开两次都是它锁定的）
- **要求引用可见文字**：防止它泛泛而谈「看起来正常」
- **预期状态要具体**：「应该弹出 X」「这条消息应该带已隐藏标记」——vision 只需对照，不需要自行推断产品意图
- **结论回灌**：vision 的观察（如「发送按钮颜色蓝/灰差异」）由主代理对照手机端/代码判定是否登记 PRD；低置信度观察登记为「待确认」级别
