# novel master 桌面端使用指南

## 这是什么

novel master 是一个专门写长篇小说的 AI Agent 工作台。桌面端是 Windows / macOS / Linux 上的 Electron 应用，界面骨架是「一顶栏 + 三栏」：左边看文件、中间管文件树、右边跟 Agent 聊天。

这份指南教你从零开始用：怎么配服务商连上 API、怎么建项目和会话、怎么把设定喂给 Agent、怎么写稿改稿、长对话怎么收敛、怎么备份和看用量。所有答案都按「入口路径 → 步骤」给，用户照着点就行。

## 核心概念速览

| 概念 | 一句话 |
|------|--------|
| **项目** | 一部作品或一个创作宇宙；它维护一份「项目工作区」当模板母本，新建会话时从这里复制一份出去。 |
| **会话** | 项目下的一次写作 / 对话线；每个会话有一份私有的「聊天工作区」，改稿互不干扰。 |
| **工作区** | 中栏那棵文件树，跟着右栏导航自动切三种视图：「会话工作区」（项目模板母本）/「聊天工作区」（当前会话私有）/「文件浏览器」（只读，看物理磁盘真实位置）。产品文档说的「三层工作区」指全局模板 → 项目模板 → 会话工作区这条复制链。 |
| **智能体** | 一个预设：系统提示词 + 可用工具名单 + 锁定模型；每个会话绑定一个，可以在会话里临时换。 |
| **技能** | 遵循 `SKILL.md` 标准的能力包，能被 `$` 引用；分全局域和项目域，项目副本会覆盖同名全局技能。 |

## 术语四词

这四个词只出现在消息操作菜单和会话详情抽屉里，说清楚就不容易懵：

- **置位**：把某条消息设成「可见历史的起点」，它前面的旧消息隐藏掉但还在；适合章节之间开新话题时收敛上下文。
- **回滚**：把会话退回到某条消息的状态，砍掉它之后的对话与改动；常带二次确认，快照丢失时还有降级确认。
- **压缩**：把最旧的一段可见消息隐藏掉——它们不再进入后续上下文，但数据仍保留（界面里降透明度显示）；既能按 token 阈值自动触发，也能手动点一次。
- **分叉**：从某条消息起在同一项目里复制出一个新会话（自动起名）继续写，原会话原样保留，相当于存档重开；分叉后直接切进新会话。

## 写法约定

回答用户的时候按这几条来：

1. **先给入口路径，再给步骤**。开头先写一行「入口：顶栏 ⚙ 设置 → AI · 服务商配置」，然后才第 1 步、第 2 步。用户最需要的是知道从哪儿点进去。
2. **同屏多个入口要列全**。同一个界面能从好几处到达（比如打开技能详情可以走技能管理、会话技能面板、或聊天里的 skill 工具卡），把三条路都写出来，用户才找得到自己那条。
3. **引用界面文案用「」原样包起来**，比如「压缩上下文」「推送到项目工作区」，让用户能在屏幕上按字找。
4. **隐藏入口要点名**。栏位显隐按钮、输入框工具栏的 `⋯`、消息右键、工作区右键的三套菜单、工具卡点击优先级——这些用户找不到但高频用，必须主动说。
5. **不确定的细节要模糊化**。比如服务商详情的两个页签哪个是默认页签、统计图表的形态，素材里没坐实，就写「页内双 tab」这种程度，不要编一个确定的说法。
6. **每节结尾可以带「常见坑」**，把用户最容易踩的写出来，比如「Windows 上原生菜单栏是隐藏的，关于要走设置页」。

不要在回答里堆内部实现术语，也不要编造素材里没有的入口。写教程的目标是用户照着点得通，不是显得专业。
