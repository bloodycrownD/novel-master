# 服务商、API 连接与模型管理

这一篇回答两类问题：「我怎么设置服务商」「我怎么连接 API」，顺带把模型怎么管、采样参数怎么调、默认模型怎么切一起讲掉。

---

## 概念先理顺

一层套一层，别混：

```
服务商（Provider）  = 一套 API 连接：协议 + Base URL + API Key
  └─ 模型（Model）   = 这套连接下可用的某个具体模型，可以有多个
       └─ 采样配置   = 这个模型自己的上下文上限和生成参数
```

Agent 最终用哪个模型，由三处决定，优先级从低到高：**工作区默认模型** → **智能体锁定的专属模型** → **会话级覆盖**。

---

## 一、设置服务商

**入口：顶栏 ⚙ 设置 → AI · 服务商配置**

1. 列表页能看到所有服务商，每行副标题写着「N 个模型 · API Key 状态」。
2. 点「新建服务商」进表单，填：
   - **协议**：openai / anthropic / gemini 三选一。内置服务商的协议是锁定的，改不了。
   - **Base URL**：接口地址。
   - **服务商名称**：自己起个显示名。
   - **API Key**：留空是「不修改」（编辑时），不是清空。
   - **Headers JSON**：额外请求头，需要透传网关标识时填。
   - **自定义参数 JSON**：原样合并进请求体顶层，可以覆盖标准字段。
3. 点保存。列表页每行 `⋯` 可以重命名 / 删除，也能点「管理」批量删。

---

## 二、连接 API 的三种典型场景

### 场景 A：官方直连

协议选对应厂商（openai / anthropic / gemini），Base URL 填官方地址，API Key 填官网拿的。保存完直接去「模型管理」拉模型。

### 场景 B：中转站 / 第三方网关（最常见）

中转站一般只提供 OpenAI 兼容协议，所以：

1. 协议选 **openai**（兼容家），不要因为服务商名字带 anthropic 就选 anthropic——要看它实际暴露的接口格式。
2. **Base URL 填中转地址**，一般形如 `https://你的中转域名/v1`，以中转站文档给的为准，带不带 `/v1` 别自己猜。
3. API Key 填中转站发的 key（通常是 `sk-` 开头，但不是硬性）。
4. 如果中转站要求自定义请求头（比如额外的 token 头），填进 **Headers JSON**。
5. 需要覆盖生成参数默认值（比如强制关掉服务商不认的参数），用 **自定义参数 JSON**，它会原样合并进请求体顶层。

拉模型之前建议先点「测试连接」类的校验步骤确认 key 和地址通不通——「拉取模型」失败时，弹窗会提示你回去检查 API Key 与 Base URL。

### 场景 C：自建 / 私有端点（vLLM、Ollama、one-api 等）

跟场景 B 一样走 openai 兼容协议，Base URL 填自己那台服务地址。这种端点常常不提供模型列表接口，遇到「拉取模型」拉不到东西时，直接用「添加」手填厂商模型 ID 就行。

## 三、模型管理

**入口：设置 → AI · 服务商配置 → 点进某个服务商**

详情页内是双页签：「服务商配置」和「模型管理」。模型管理这一侧有三块：

### 已保存模型列表

每行显示模型名和状态，行 `⋯` 有三个动作：
- **编辑** → 打开采样配置页。
- **重命名**
- **删除**

也能批量删除（含全选）。如果两个模型用了同一个厂商 ID，会在下面显示厂商 ID 当副标题帮你分辨。

### 拉取模型

点「拉取模型」弹窗：
1. 从这个服务商拉一份模型列表回来。
2. 用文本框过滤想找的那几个。
3. 全选 / 全不选按钮在顶部。
4. 多选后点添加。已经加过的模型标着「已添加」并且不可选。
5. 拉取失败有「重试」按钮。

### 添加（手填）

点「添加」，手填厂商模型 ID，模型名称可选。留空就用厂商 ID 当名称。输入框里按 **Enter** 直接提交。

## 四、采样配置

**入口：模型管理列表 → 点某个模型行 →「编辑」**

1. **模型名称**：显示用名字，旁边有派生展示名（服务商 / 模型名）方便你在别处认出来它是谁。
2. **内部预算**：上下文上限 tokens，以及计数方式。这个值影响会话上下文占用条算得准不准，按你实际用的模型填。
3. **生成参数**：按协议分组的表单（不同协议能填的字段不一样），另有思考强度分段控件（模型支持思考时才出现）。
4. 点「恢复默认」可以扔掉改动回到出厂值。
5. 保存后以本页为准。

## 五、选择「当前模型」的三处入口

同一个「选模型」的动作有三个地方，分工不同：

| 入口 | 作用范围 | 路径 |
|------|----------|------|
| **工作区默认** | 全局默认，新建会话的起点 | 设置 → 工作区 · 常规 →「默认选择」→「当前大模型」→ 点行弹选择框 |
| **智能体专属** | 绑死在这个智能体上 | 设置 → AI · 智能体配置 → 编辑某个 Agent →「模型」区（默认是「跟随」） |
| **会话覆盖** | 只影响这一个会话 | 会话里点输入框工具栏 `⋯` →「会话详情」抽屉 →「模型」→ 点行选 |

三者优先级：会话覆盖 > 智能体专属 > 工作区默认。

**注意锁定态**：当模型来自智能体锁定时，抽屉里的模型卡会显示 🔒「智能体锁定」，此时会话内没法覆盖。想改，得去改智能体的模型设置。

模型选择器是空的？说明一个模型都还没配，去上面第三节添加一个。

## 常见坑

1. **Base URL 到底带不带 `/v1`？** 别猜，看服务商文档；不确定就先按带的试，报 404 就去掉再试。中转站尤其容易在这栽。
2. **协议选错了表现为「连上了但答非所问」或者直接 400。** 中转站绝大多数是 OpenAI 兼容协议，就算它家主力模型是 Claude 也一样，协议按接口格式选，不按模型选。
3. **编辑服务商时 API Key 留空会不会把 key 抹掉？** 不会，留空就是「不修改」。想清空得走专门的清除动作。
4. **拉取模型拉不到，但 key 明明是对的。** 很多自建 / 中转端点根本没实现模型列表接口，直接用「添加」手填厂商 ID 更快。
5. **「已添加」不能选是 bug 吗？** 不是，防止重复添加同 ID 模型。
6. **自定义参数 JSON 是不是越少越好。** 是。它会原样合并进请求体顶层并且能覆盖标准字段，塞错一个 key 整个请求就可能被服务商拒。
