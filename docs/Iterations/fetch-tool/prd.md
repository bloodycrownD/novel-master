# agent fetch 网络请求工具 PRD

## 背景

agent 的内置工具（read/write/edit/fs/glob/grep/task/skill/agent）全部操作本地 VFS，**没有任何联网能力**。创作与答疑中常需要「查一下这个网页/接口文档/在线资料」，目前 agent 只能请用户手动粘贴内容。

用户希望新增内置 `fetch` 工具，让 agent 直接发起网络请求获取 URL 内容。技术预研结论（双端 HTTP 栈已被云同步等模块验证）确认无需平台分包，双端同构可行。

## 目标（含成功指标）

| 目标 | 成效指标 |
|------|----------|
| 联网能力 | agent 可对 http/https URL 发起 GET 请求并拿到响应正文 |
| 双端可用 | desktop / mobile 行为一致，无平台差异感 |
| 安全可控 | 仅 http/https；响应体积有截断保护；用户可通过工具策略 allow/deny 收回 |
| 结果可读 | 返回内容结构清晰（状态、类型、正文），大响应有明确截断提示 |

## 用户与场景

| 用户 | 场景 |
|------|------|
| 创作用户 | 「帮我查这篇文章的原文」→ agent fetch 网页并基于内容续写/批注 |
| 开发者用户 | 让 agent 拉取接口文档、开源文件内容辅助编码 |
| 普通用户 | 不想给 agent 联网能力时，在智能体配置中 deny fetch 即可 |

## 范围
### 包含范围
- 内置 `fetch` 工具（GET 请求、返回状态码/内容类型/正文文本）
- 响应体积截断保护与截断提示
- 工具目录登记（智能体配置 UI 中可 allow/deny）
- 双端（desktop / mobile）一致可用

### 不包含范围
- POST/PUT 等写操作方法与自定义请求头/Body（本期只读 GET）
- 鉴权站点（登录态、API Key 管理）
- HTML→纯文本/Markdown 的智能降噪（本期原样返回正文，降噪作为风险项评估）
- 二进制/图片内容的结构化返回（正文按文本处理）
- 代理配置与网络诊断
- CLI 端适配验证

## 核心需求（3-7 条）

1. **基础请求**：输入 URL（仅 http/https），发起 GET 请求，返回状态码、内容类型与正文文本。
2. **超时与错误**：请求超时与网络错误返回可读的错误信息（含原因），不中断会话。
3. **体积保护**：响应正文超过阈值时截断，并明确标注已截断与原始大小，避免巨响应撑爆上下文。
4. **工具目录**：智能体配置的工具清单中出现 fetch，用户可按现有 allow/deny 机制控制（含子代理策略沿用现有工具策略机制）。
5. **默认可用**：注册即为内置工具，无需额外开启；不放心者可全局 deny。
6. **内容安全**：仅允许 http/https 协议，拒绝 file:// 等其它协议。

## 验收标准

- Given agent 被问及某在线文档，When 模型调用 fetch(https URL)，Then 工具返回状态码 200、内容类型与正文文本，模型可基于内容回答。
- Given URL 返回超大正文（如 >100KB），When fetch 完成，Then 返回被截断的正文并附「已截断，原始 N 字节」提示，会话不崩溃。
- Given URL 为非 http/https 协议（如 file://），When 模型调用 fetch，Then 工具返回协议不支持的错误，不发起请求。
- Given 网络不可达或超时，When fetch 完成，Then 返回可读错误信息（含原因），agent 可向用户解释。
- Given 用户在智能体配置中 deny fetch，When 该 agent 运行，Then 工具清单不含 fetch、模型无法调用。
- Given desktop 与 mobile 分别运行同一请求场景，Then 行为与返回结构一致。
- Given 工具返回结果进入聊天记录，When 查看消息详情，Then 结果以可读文本形式呈现（非原始 JSON 串）。

## 风险与待确认项

- **SSRF/内网防护**：是否需要拦截私网地址（127.0.0.1、192.168.x.x 等）待拍板；本期至少不做内网穿透型用法引导。
- **HTML 降噪**：网页原样返回时标签噪音大、有效正文占比低，可能需要后续迭代引入正文提取。
- **mobile RN 网络行为**：gzip 自动解压、非常规 Content-Type 等边界需在双端实测覆盖。
- **子代理策略**：fetch 默认对子代理可用（沿用统一工具策略），若需单独禁用深层代理联网，实现时在工具策略层评估。
