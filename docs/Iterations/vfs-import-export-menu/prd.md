# VFS 工作区导入导出菜单收敛 PRD

## 背景

双端 VFS 工作区（会话工作区 / 项目工作区）的文件管理菜单目前把导入导出**按实现形式平铺**：桌面端空白区与目录行右键菜单各有「导入 ZIP / 导入角色卡 / 导出 ZIP」三项（`workspace-context.ts` 的 `workspaceMenuItems()` 单源）；移动端目录长按菜单与顶栏 ⋯ 菜单把同样三项**各写了一遍**（`VfsFileManager.tsx` 的 `entityMenuItems` / `moreMenuItems`）。

这带来三个问题：

1. 菜单按实现形式而非用户意图组织，形式平铺占位多、双端还各写两遍；
2. 「单文件」这个最常见诉求没有菜单通道——桌面端只有拖拽手势（拖入导入 / 拖出导出），移动端完全没有；
3. 文件行菜单没有任何导出入口，单个文件想拿到本地只能靠桌面拖拽。

能力现状（探索结论，报告存 `tmp/explore-import-export-{1,2,3}-*.md`）：zip 导入/导出、角色卡导入双端完整可用（语义均为目标目录**整子树覆盖**）；单文件导入/导出的 core 能力已存在（batch-io 通道：`planBatchIngest` / `planBatchExport`），桌面端已接但绑死拖拽手势、无文件对话框通道，移动端零接入；角色卡导出完全不存在（本次不需要，导出形式恰好不含它）。

## 目标（含成功指标）

- **菜单收敛**：所有导入导出入口收敛为「导入」「导出」两项，按形式命名的菜单项全部退役。
- **单文件能力菜单化**：双端补齐单文件导入与单文件导出的菜单入口（桌面端从拖拽专属提升、移动端从零补齐）。
- **行为统一**：单文件导入与 zip/角色卡导入走统一链路——session 作用域导入后清理会话提示词缓存（规则快照 + 文件缓存）。

成功指标：双端 VFS 工作区菜单不再出现按形式命名的导入导出项；单文件导入/导出在双端均可从菜单完成；导出操作不新增任何选择弹窗（比原方案少一次选择）。

## 用户与场景

用户在 VFS 工作区管理文件（会话工作区 = 聊天页「工作区」面板；项目工作区 = 会话列表页「项目工作区」面板；桌面端为文件树面板）：

- 想把外部**一个文件 / 一个 zip 包 / 一张角色卡**放进工作区当前目录（或被选中的目录）→ 点「导入」→ 在弹窗里选形式；
- 想把工作区里**某个文件**拿到本地 → 在该文件行的菜单点「导出」；
- 想把工作区里**某个目录（或整域）打包**导出 → 在目录行 / 空白区菜单点「导出」。

## 范围

### 包含范围

- 桌面端 + 移动端 VFS 工作区文件管理菜单的收敛改造（空白区 / 目录行 / 文件行 / 顶栏全部相关菜单）。
- 「导入」形式选择弹窗（单文件 / zip 包 / 角色卡三选）。
- 文件行「导出」入口（新增）与目录 / 空白区「导出」（zip，行为沿用现状）。
- 单文件导入、单文件导出能力补齐：桌面端新增文件对话框通道；移动端新增服务层。
- session 作用域下，单文件导入清理规则快照与文件缓存（与 zip/角色卡导入同链路）。

### 不包含范围

- 技能域的导入导出（技能管理页 / 新建技能弹窗维持现状）。
- 角色卡导出（能力不存在，也不在本次目标内）。
- 批量 / 多选导入。
- 桌面端拖拽导入导出链路（维持现状不动）。
- CLI。

## 核心需求（5 条）

**R1 菜单收敛（双端）**：桌面端空白区 / 目录行右键菜单与移动端目录长按菜单、顶栏 ⋯ 菜单中，「导入 ZIP / 导入角色卡 / 导出 ZIP」三项退役，改为「导入」「导出」两项；移动端两处菜单的重复定义收敛为同源常量。移动端文件行长按菜单与桌面端文件行右键菜单**新增「导出」**项。

**R2 导入形式选择**：点「导入」弹出形式选择（单文件 / zip 包 / 角色卡），选择后进入各自链路。三种导入的覆盖确认**文案各自独立、不得混用**：zip = 将覆盖目标目录下全部内容；角色卡 = 将覆盖目标目录；单文件 = 同名文件需确认后覆盖。

**R3 导出类型直达（无选择弹窗）**：菜单上下文已知操作对象类型，「导出」直接分流——文件行 = 单文件导出该文件（桌面端系统另存为对话框；移动端系统保存面板）；目录行 / 空白区 / 顶栏 = zip 导出目标目录（默认文件名沿用现有推导规则）。导出方向不出现形式选择弹窗。

**R4 单文件导入（新增能力）**：桌面端从拖拽专属提升为菜单入口 + 文件选择对话框（复用现有批量导入服务）；移动端新增（系统文件选择器 → 写入目标目录）。目标目录已有同名文件时必须经用户确认覆盖后才写入。

**R5 缓存清理统一**：session 作用域下单文件导入与 zip / 角色卡导入行为一致——事务提交后清理该会话的规则快照（rule_snapshot）与文件缓存（file_cache），使下一轮提示词按新文件重评工作区前缀。清理落点与既有导入同链路（core 服务内 session 分支），双端一致。

## 验收标准

1. **菜单收敛（桌面）**：Given 任意可写工作区面板，When 空白区或目录行右键，Then 菜单含「导入」「导出」且不含「导入 ZIP / 导入角色卡 / 导出 ZIP」；When 文件行右键，Then 含「导出」、不含「导入」。
2. **菜单收敛（移动）**：Given 会话工作区或项目工作区面板，When 长按目录行或点顶栏 ⋯，Then 同上口径；When 长按文件行，Then 菜单含「导出」。
3. **导入三选**：When 点「导入」，Then 弹窗含且仅含「单文件 / zip 包 / 角色卡」三项；选 zip 或角色卡走现有链路（含整树覆盖确认与结果提示）；选单文件弹出系统文件选择器，取消则静默返回不报错。
4. **单文件导入**：When 选择一个文本文件并确认导入目标目录，Then 该目录出现此文件且内容一致；When 目标已有同名文件且用户未确认覆盖，Then 不写入；When session 作用域导入成功，Then 该会话的规则快照与文件缓存被清空（与 zip 导入同口径）。
5. **单文件导出**：When 文件行点「导出」并确认保存位置，Then 本地得到内容一致的单文件、全程无形式选择弹窗；When 目录行 / 空白区点「导出」，Then 走 zip 导出且行为与现状一致。
6. **回归不变**：现有 zip / 角色卡导入导出行为不变；桌面端拖拽导入导出不变；技能域入口不变；physical 只读面板不出现导入导出项。
7. **测试与 e2e**：桌面 `workspace-zip-menu` / `workspace-character-card-menu` 断言按新菜单结构改写并通过；E2E `case-zip-backup` 按收敛后流程（经「导入/导出」入口）通过；移动端 `vfs-character-card-menu` 源码契约改写并通过。

## 风险与待确认项

- **单文件导入默认严格单选**（菜单语义即「单文件」）；是否放开多选留待后续需求，本次不做。
- **二进制文件的行为**：core 批量导入通道现状对非 UTF-8 文件「静默跳过」，菜单化后应避免静默——spec 阶段二选一：选择器端过滤（只允许常见文本类型）或导入后明示「已跳过非文本文件」。
- **桌面端会话工作区的 scope 历史命名**：workspaceScope `session` 在桌面端实际解析为 project kind，缓存清理门闸以「与 zip 导入完全同族一致」为准，spec 阶段对齐验证。
- **移动端单文件导出的文件名 / MIME 推断**：在 `document-io` 现有扩展名映射基础上覆盖常见类型，避免保存面板出现无名/错误类型文件。
