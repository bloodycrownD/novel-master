# markdown 代码块渲染（块级形态 + 语言标签 + 语法高亮）PRD

## 背景

用户反馈 markdown 预览中**代码块渲染效果与行内代码一样**。探索定位到双端成因不同：

- **mobile 聊天与 .md 预览**（WebView 主路径）：代码块容器 `pre` 只有折行规则，**没有背景/边框/内边距，也没有行内样式重置**——围栏代码块内层的 `code` 直接带着行内代码样式渲染，整块看起来就是一大段行内代码（与用户描述完全吻合的根源）。
- **desktop 预览与聊天**：`pre` 有块级规则，但背景/边框色值与行内代码相同，且全链路无语法高亮，区分度弱。

全链路（desktop react-markdown、mobile markdown-it、RN 回退路径）**均无语法高亮**，唯一特判语言是 mermaid。用户拍板做到第三档：**块级视觉形态 + 语言标签 + 语法高亮**。

既有约束：mobile 代码块**折行是故意设计**（避免块内横向滚动抢走聊天竖滑手势）；批注功能以渲染后文本为坐标基准（高亮向文本插入元素需保证批注不回归）；mobile 聊天与 .md 预览共用一份样式单源。

## 目标（含成功指标）

| 目标 | 成效指标 |
|------|----------|
| 块级形态 | 双端围栏代码块具备独立背景/边框/内边距/圆角，与行内代码视觉明确区分 |
| 语言标签 | 代码块顶部显示语言名（如 `typescript`），未标注语言时优雅降级 |
| 语法高亮 | 常用语言（ts/js/json/python/bash/sql/markdown 等）双端一致高亮；明暗主题均成立 |
| 约束保持 | mobile 保留折行设计；mermaid 渲染行为不回归；批注定位不回归 |
| 双端一致 | 同一内容在 desktop 预览/聊天与 mobile 预览/聊天的代码块形态一致（风格可随平台微调） |

## 用户与场景

| 用户 | 场景 |
|------|------|
| 创作用户 | agent 输出带代码示例的写作指导时，能看清代码结构而不是一片灰色行内块 |
| 开发者用户 | 在 .md 文件预览与聊天中阅读代码片段，语法高亮提升可读性 |
| 批注用户 | 在文件预览上对含代码的文档划词批注，定位不受高亮影响 |

## 范围
### 包含范围
- mobile WebView 主路径（聊天 transcript + .md 预览，共用样式单源）：块级形态 + 语言标签 + 高亮
- desktop 预览与聊天两条场景：块级形态强化（与行内区分）+ 语言标签 + 高亮
- mobile RN 回退路径：维持纯文本现状（回退组件不渲染 markdown，仅做「行为不变」回归验证）
- 流式期间已完成的代码块按新形态渲染

### 不包含范围

- 代码块复制按钮、行号、折叠（可作后续迭代）
  - 范围变更批注（release-1.5.6 追认）：复制按钮经用户口头追加已实施（desktop `CodeCopyButton`；mobile `code-copy.ts` + fence 注入 `span.code-copy` + `copyCode` 桥 + CSS，详见 spec 变更点 C-14~C-17），随 release-1.5.6 追认纳入范围（mermaid 块除外，与 desktop 图表渲染口径对齐）；行号、折叠仍不在范围
- 代码编辑器（FileEditor）的编辑态高亮
- 自定义高亮主题配置（跟随应用明暗主题即可）
- 流式进行中未闭合代码块的实时高亮（流式轻量渲染维持现状）
- CLI 端

## 核心需求（3-7 条）

1. **块级形态**：围栏代码块具备独立背景、边框、内边距与圆角，宽度占满内容区；行内代码保持现有紧凑样式；mobile 保留折行（不做块内横向滚动）。
2. **语言标签**：代码块顶部显示 fence 标注的语言名；未标注语言时显示通用标识或不显示标签（降级自然）。
3. **语法高亮**：常用语言清单（至少：typescript/javascript/json/python/bash/shell/sql/markdown/yaml/html/css）按 token 高亮；高亮配色跟随明暗主题；不支持的语言降级为纯文本块级形态。
4. **mermaid 不回归**：mermaid 代码块继续走图表渲染链路，不套用普通代码块形态，全屏查看器行为不变。
5. **批注兼容**：高亮与形态改动后，文件预览上的划词批注定位与回显不回归。
6. **RN 回退路径**：超长文本/引擎回退场景维持纯文本现状（回退组件按源码原样展示，本迭代不改动其渲染行为，仅保证不回归）。

## 验收标准

- Given mobile 聊天消息含 ```ts 围栏代码块，When 渲染完成，Then 代码块呈块级容器（背景/边框/内边距/圆角）且带 `typescript` 语言标签，与行内 `code` 视觉明确不同。
- Given 同一消息含高亮清单内语言代码块，When 双端分别渲染，Then 关键字/字符串/注释等待到高亮且配色协调（明暗主题各验证一轮）。
- Given 代码块未标注语言，When 渲染，Then 仍呈块级形态，无报错、无空标签残留。
- Given 代码块语言不在支持清单（如冷门语言），When 渲染，Then 降级为纯文本块级形态，不报错。
- Given mobile 含长行代码块，When 渲染，Then 代码折行展示，块内不出现横向滚动，聊天竖滑不受影响。
- Given mermaid 代码块，When 渲染，Then 继续渲染为图表（含全屏入口），不显示为普通代码块。
- Given 含代码块的 .md 文件，When 用户划词批注并保存后重开，Then 批注定位与回显正确。
- Given 超长 .md 触发 RN 回退路径，When 预览，Then 纯文本回退行为不变（源码原样展示、不报错、无渲染回归）。
- Given 流式输出中出现已闭合的代码块，When 流式继续，Then 该代码块按新形态渲染且不闪烁错乱。

## 风险与待确认项

- **批注文本流影响**：高亮会向代码文本内插入着色元素，批注量测基于渲染后文本——需重点回归（mermaid 迭代有保留源码隐藏节点的先例可参考）。
- **安全白名单**：mobile 渲染前的 HTML 净化白名单需放行高亮所需的元素与样式类，同时不放松整体安全基线。
- **双端渲染器差异**：desktop（react-markdown 系）与 mobile（markdown-it 系）高亮实现不同源，需用同一组样例内容做双端一致性验收。
- **高亮库体积**：mobile WebView 注入体积与性能需实测（长文档多代码块场景）。
