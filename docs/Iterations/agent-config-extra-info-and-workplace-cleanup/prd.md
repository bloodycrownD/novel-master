# Agent 配置附加信息与遗留清理 PRD

## 背景

这次围绕「agent 配置」和「消息附加」做三件互相独立、但都属于体验打磨与历史欠账清理的事。前序探索已确认现状，三件事的来龙去脉是这样的：

1. **mobile 表单页键盘遮挡**：mobile 的 agent 配置页（以及其它所有走公共表单壳 `ScreenFormLayout` 的页面）整条链路没有任何键盘避让处理。一旦点到底部的多行输入框，弹起的软键盘会直接盖住正在编辑的那一行，下面也没法滑出来。聊天页和文件编辑页早就踩过同一个坑，并且沉淀了一套「收缩裁切窗口」的做法（注释里反复强调：不能只靠 `translateY` 顶上去，因为内容区是 `flex:1` 不会自动缩，平移后顶部会被外层 `overflow:hidden` 裁掉、滚不回去）。这套现成方案目前没有惠及表单页。

2. **缺少「自定义附加信息」入口**：现在用户给 agent 发消息时，除了正文和 `@文件引用`，没有一种便捷的方式给模型补充一段固定的背景说明（比如「当前目录结构为……」「本次写作要遵守某某风格」）。用户希望 agent 配置里有个开关，打开后出现一个输入框，把这段固定文本作为常驻附加信息，每次发消息时自动拼到用户消息里。仓库里已经有一套完整的消息附件/拼装管线（`message-attachment-unified`），但目前没有承载这种「纯文本常驻背景」的位置。

3. **workplace 附件已是死代码**：经过全链路核实，消息附件里 `source: "workplace"` 这条路径已经没有任何活的写入来源——三端发送都不传它，核心层入口会显式过滤掉误传的 workplace，核心层内部也没有任何构造它的代码点，曾经推送 workplace 差集的 IPC 也已废止。现在 workplace 走的是完全独立的「常驻前缀」路径，根本不再构造附件。但 schema 的 source 枚举、`prepare` 阶段的 `hydrateWorkplaceWithSeen` 分支、`workplaceChange` action 枚举、chip 分流判断、以及大量测试里仍然残留着这条死路径，注释也还把 workplace 当成活路径描述，和实际行为不一致。需要把这部分遗留清掉，让代码与现状对齐（注意：`source: "attach"` 仍由核心层扫描正文 `@路径` 生成，是活路径，不在本次清理范围内）。

## 目标（含成功指标）

- **键盘体验对齐**：mobile 表单页的键盘避让行为与聊天页一致——软键盘弹起时页面被输入区顶起，底部输入项不被遮挡，顶部内容不被裁掉、仍可正常滚动滑下来。
  - 成功指标：所有走 `ScreenFormLayout` 的表单页（agent 编辑、项目级 agent 配置、Provider、CloudSync、Events、ModelSampling、CompactionConditions）在 Android 与 iOS 上键盘弹起后均无遮挡、可滚动。
- **自定义附加信息可用**：用户可以在 agent 配置里开启一个开关并填写附加信息，发送消息时这段文本以约定格式拼到用户消息中，模型可读取。
  - 成功指标：开关开启并填写内容后，任意一条用户消息发送时，提示词里都能稳定出现对应附加块；开关关闭时不出现。
- **workplace 死代码清除**：移除消息附件链路中所有已无写入来源的 workplace 残留，代码与注释回到「与现状一致」的状态，历史会话数据仍可正常读取。
  - 成功指标：核心层不再保留 workplace 的新写入/读取分支（除兼容历史数据所必需者），相关注释与文档不再把 workplace 描述为活路径。

## 用户与场景

- **mobile 用户编辑 agent 配置**：在手机上配置 agent 的系统区/动态区/会话区等长表单时，需要频繁编辑底部的多行输入框，软键盘弹起后希望像聊天页一样被自然顶起、内容不被吃掉。
- **希望给 agent 补充固定背景的创作者**：写作时希望给模型常驻一段「当前目录结构」「写作风格约定」之类的背景说明，不想每次手动复制粘贴到正文里。
- **维护代码库的开发者**：希望消息附件链路的代码清爽、注释准确，不被 workplace 这种已经废弃的路径误导。

## 范围

### 包含范围

- mobile 端公共表单壳的键盘避让修复（Android 收缩裁切窗口 + iOS 键盘避让），惠及所有使用该壳的表单页。
- agent 配置新增「自定义附加信息」开关 + 输入框（mobile 与 desktop 双端，全局 agent 与项目级 agent 两条入口）。
- 该附加信息在发送消息时按约定格式拼装进用户消息提示词。
- workplace 附件死代码的移除（schema 枚举收窄、`prepare` 分支清理、`workplaceChange` action 清理、chip 分流清理、相关测试与过时注释修正）。

### 不包含范围

- `source: "attach"` 附件链路的任何改动（它由核心层扫描正文 `@路径` 生成，是活路径）。
- workplace「常驻前缀 S0」路径（`assembleWorkplaceDisplay`）的改动——它和附件链路是两套独立机制，本次不碰。
- 附件拼装的对外协议大改（仍沿用 `message-attachment-unified` 既有的 `<attachment>` 外层结构）。
- 桌面端的键盘遮挡问题（桌面端不存在 mobile 那种软键盘顶起布局，无需改动）。
- 表单页之外其它页面的键盘体验。

## 核心需求

### 1. mobile 表单页键盘避让对齐聊天页

公共表单壳需要在软键盘弹起时，让内容区真正收缩到键盘上方（而不是简单平移），保证底部输入项可见、顶部内容不被裁、整页仍可滚动。底部按钮条保持文档流贴底（不改为浮层）。Android 与 iOS 各自采用与聊天页/文件编辑页一致的策略。修在公共表单壳一处，让所有复用它的表单页一并受益。

### 2. 自定义附加信息开关（agent 配置）

在 agent 配置里提供一组「开关 + 输入框」：开关关闭时只显示开关；开关打开后出现多行输入框，供用户填写一段常驻附加信息。开关与内容的存储方式对齐现有 `system`/`workplace` 区的「单字段承载」做法——即内容非空视为开、空视为关。该配置对全局 agent 与项目级 agent 都生效。

### 3. 附加信息的消息拼装

开关开启且填写了内容时，用户每次发送消息，这段附加信息要以独立的纯文本块拼进用户消息提示词，位置在 `<user-ops>` 之后、`<user-input>` 之前，格式如下（`{附加信息文本}` 即用户填写的内容）：

```
<attachment>
  <user-ops>
    {文件操作/批注等 action XML}
  </user-ops>
  <extra-info>
    {附加信息文本}
  </extra-info>
</attachment>
<user-input>
{用户正文}
</user-input>
```

当附加信息为空（开关关或内容空白）时，整个 `<extra-info>` 块省略，与现有对空附件的处理保持一致。该文本块是纯文本，不套用 action XML、不混进 `<user-ops>`。附加信息属于常驻配置，对该 agent 的每条用户消息都生效。

### 4. workplace 附件死代码移除

清除消息附件链路中所有已无写入来源的 workplace 残留：source 枚举收窄、`prepare` 阶段的 workplace 读取分支与 `workplaceChange` action 清理、composer chip 的 workplace 分流清理、相关测试与过时注释修正。需保证历史会话数据中已有的 workplace 附件仍能被正常读取（兼容历史数据所必需的读取分支可保留或做一次性迁移，具体策略见风险章节）。

## 验收标准

### 键盘避让

- **Given** mobile 端任意一个使用公共表单壳的页面（agent 编辑 / 项目级 agent 配置 / Provider / CloudSync / Events / ModelSampling / CompactionConditions），
  **When** 用户点开底部多行输入框、软键盘弹起，
  **Then** 被编辑的输入框完整可见、不被键盘遮挡；顶部内容不被裁掉；内容区可正常上下滚动。
- **Given** 上述页面的底部保存按钮条，
  **When** 软键盘弹起，
  **Then** 按钮条贴在键盘上方，仍可点击，且不以浮层形式遮挡内容。
- **Given** `Events` 等依赖滚动开关动态切换的页面，
  **When** 键盘避让介入，
  **Then** 原有的弹层禁滚动等行为不被破坏。

### 自定义附加信息

- **Given** agent 配置中的「自定义附加信息」开关处于关闭状态，
  **Then** 输入框不显示；发送消息时提示词中不出现 `<extra-info>` 块。
- **Given** 用户打开开关并填写「当前目录结构为 xxx」，
  **When** 发送一条用户消息（正文为「帮我写第一章」），
  **Then** 提示词中出现 `<extra-info>` 块，内容为所填文本，位置在 `<user-ops>` 之后、`<user-input>` 之前。
- **Given** 开关打开但输入框内容为空白，
  **When** 发送消息，
  **Then** 提示词中不出现 `<extra-info>` 块（与空省略规则一致）。
- **Given** 该 agent 配置已开启附加信息，
  **When** 连续发送多条用户消息，
  **Then** 每条消息的提示词中都出现同一个 `<extra-info>` 块（常驻生效）。
- 该开关与内容在全局 agent 与项目级 agent 两条入口下行为一致，且关闭/重开后配置不丢失。

### workplace 死代码移除

- **Given** 任意一条新的用户消息发送流程，
  **Then** 链路中不再产生任何 `source: "workplace"` 的附件或 `workplaceChange` action。
- **Given** 核心层发送入口收到误传的 workplace 附件，
  **Then** 被安全忽略，不落库、不报错。
- **Given** 历史会话数据中存在 workplace 附件，
  **When** 打开该历史会话并渲染提示词，
  **Then** 仍能正常读取、不丢失原有内容、不抛错（兼容策略见风险章节）。
- 代码中关于 workplace 的注释与文档描述与实际行为一致，不再把 workplace 描述为活路径。

## 风险与待确认项

- **workplace 历史数据迁移策略待定**：是无限期保留读取兼容分支，还是写一次性迁移把历史 `source: "workplace"` 行归一化后再彻底删除读取分支？这会影响清理的彻底程度与回归范围，需在实现阶段拍板。
- **`<extra-info>` 块名与配置字段名为暂定**：本 PRD 采用用户指定的 `<extra-info>` 块名；agent 配置中承载该开关的字段名（产品层称「自定义附加信息」）在实现时再与现有命名约定（如 `system`/`workplace`）对齐敲定。
- **keyboard 避让改动影响面较大**：由于修在公共表单壳一处，需对全部复用页面做键盘场景回归，尤其是 `Events` 这类带滚动开关的页面，避免与既有交互冲突。
- **iOS 策略对齐**：iOS 上表单壳目前也没有键盘避让，本次一并补齐（对齐文件编辑页做法），需确认 iOS 上的体验符合预期。
