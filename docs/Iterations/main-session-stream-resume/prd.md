# 主会话流式内容重进恢复 PRD

## 背景

mobile 主会话生成进行中，用户退出会话再进入时，当前回合尚未落库的流式内容（thinking 思考过程与正文文本的已生成部分）不会恢复——重进后看到的是已落库的历史步骤，进行中那一步的进度观感上是「丢失」或「从头重新渲染了一遍」。

对照现状：项目内子会话（子代理会话）已具备该能力——无论用户何时进入子会话页，正在进行的流式内容都能接着显示；而已完成步骤的 thinking 内容本身是随消息落库持久化的，重进后正常展示。也就是说，主会话与子会话在「重进恢复流式内容」上的体验不一致，且子会话已验证过这套体验可行，主会话是能力缺失而非设计不可行。

## 目标（含成功指标）

app 存活期间，主会话生成中退出再进入，流式体验与子会话对齐：进行中步骤的已生成内容（thinking + 正文）完整续显，后续新增内容继续流式上屏，且不重复展示已落库的内容。

成功指标：

- 生成中退出重进，thinking 与正文的已生成部分无丢失、无「重新流一遍」的观感。
- 重进后「生成中」状态正确显示，后续流式增量持续上屏。
- 已落库的历史步骤不因重进被重复推送或闪烁。

## 用户与场景

- 用户：使用 mobile 主会话与 agent 长对话的用户（长回复生成耗时较长，中途离开页面是高频动作）。
- 场景一：用户发起一轮生成，agent 正在输出思考内容时用户切到别的会话或页面，稍后回到本会话，期望看到思考与正文已经生成到哪了、并继续往下流。
- 场景二：用户重进后停留在会话页，期望后续生成无缝继续上屏，直到回合正常结束，最终落库内容与所见一致。
- 场景三：用户在生成中重进多次（反复进出），期望每次都恢复到当前进度，不出现内容重复或错乱。

## 范围

### 包含范围

- mobile 主会话（聊天页）生成中退出重进的流式内容恢复，thinking 与正文一视同仁。
- 重进后「生成中」状态与后续流式增量的持续接收。
- 重进恢复与已落库内容的边界正确性（不重复推送已落库步骤）。
- 用户主动停止（abort）后保留 partial 的既有行为不回退。

### 不包含范围

- 应用进程被杀 / 崩溃后的恢复（进程死亡时进行中的流 inherently 无法保留，仅已落库步骤存活；该场景与「退出后保持请求」同属会话生命周期话题，另行立项）。
- 多会话并行、退出会话后请求保活、完成通知（用户已确认另行处理）。
- 生成中「轮数上限导致状态残留」问题（用户已确认另行处理）。
- desktop 端主会话（本次聚焦 mobile）。
- 落库持久化结构变更（已落库 thinking 的保存机制现状已满足，无需动）。

## 核心需求（3-7 条）

1. 主会话生成中退出重进，进行中步骤已生成的 thinking 与正文内容完整恢复显示，进度与退出时一致。
2. 重进后「生成中」状态正确呈现，后续流式增量继续实时上屏直至回合结束。
3. 恢复边界以「已落库步骤」为界：已落库内容按历史消息正常展示，不参与流式重放，杜绝重复推送与闪烁。
4. 反复多次退出重进，每次恢复结果一致且内容不错乱。
5. 用户主动停止生成时的 partial 保留行为（现有能力）不受影响。

## 验收标准

- Given 主会话生成中（thinking 流式输出至一半），When 用户退出会话再进入，Then 已生成的 thinking 与正文内容完整显示、无丢失，「生成中」状态在位。
- Given 用户重进后停留在会话页，When 后续增量到达，Then 内容从当前进度继续流式上屏直至回合结束，最终所见与落库内容一致。
- Given 生成中反复退出重进三次，When 每次重新进入及回合结束，Then 每次进入均恢复到当前进度（不丢失、不因重复恢复出现重复段），回合结束后消息内容无重复段、无错乱，历史展示正常。
- Given 生成中用户点停止，When 重进会话，Then partial 内容按现有 abort 保留口径展示（不回退）。
- Given 一轮正常完成的会话（无进行中生成），When 用户退出重进，Then 行为与现状一致（历史消息静态展示，无额外流式表现）。
