# huge-card-import-crash Bug PRD

## 背景

角色卡导入（`Iterations/character-card-import` 交付的能力）上线后，有终端用户导入一个巨大的角色卡（超大 PNG 内嵌元数据或超大 JSON），应用当场崩溃，且此后每次启动都在进入主界面前崩溃，应用完全不可用（崩溃循环）。

## 现象描述

1. 导入巨大角色卡时应用直接崩溃（进程被杀，非可恢复的界面报错）。
2. 重启应用仍无法进入——崩溃循环，用户被彻底锁在应用外。
3. 用户侧无法自行取出数据库文件（应用私有目录 + release 包不可调试），唯一的出路是装上修复版。

## 复现步骤

1. 准备一个巨型角色卡（体积远超常规 5–10MB 的重度世界书卡）。
2. 工作区进入目标文件夹 → 更多 → 导入角色卡 → 选中该卡并确认。
3. 观察导入过程应用被杀。
4. 重新打开应用：启动后仍在崩溃前链路上死亡，无法进入主界面。

## 预期行为

- 导入侧：超大卡片被明确拒收，给出「角色卡过大」的用户可读报错；应用保持存活、其它功能不受影响。导入成功路径的容量优化（分块、流式解析）**不在本期范围**，本期允许「导入失败」。
- 读取侧：即便毒数据已在此前版本落库（升级用户），应用也必须能启动、能进主界面；被毒数据污染的会话上下文组装对超大文件降级为占位提示，用户可通过工作区文件管理删除毒目录自救。

## 实际行为

- 导入无任何体积/条目上限：巨型输入在解析链上产生多份全尺寸内存拷贝（base64 → 解码 → JSON.parse → SQLite 绑定），触发原生 OOM，try/catch 全部失效、进程被杀。
- 落库后重启：会话恢复链路（token 标签计算）对工作区启用文件逐个全文读取并拼接巨型字符串，再次 OOM，形成崩溃循环。

## 影响范围

- mobile（重灾区，内存最紧）；desktop/CLI 共用 core 导入实现，同受 core 层新闸门保护。
- 读取侧降级在 core，mobile/desktop 的会话上下文组装同时受益。

## 验收标准

1. 导入超过阈值的卡片：不落库、不崩溃，界面提示导入失败原因；48MB 输入上限 / 32MB 内容总量 / 8MB 单文件 / 5000 条目，任一超限即拒收。
2. 存量毒库（升级前已导入巨大卡片的库）：应用可正常启动进入主界面；超大文件在工作区上下文组装中显示「（文件过大，已跳过，约 N 字符）」占位；用户可在工作区文件管理中删除相关目录。
3. 正常大小卡片（含 5–10MB 重度世界书卡）导入与使用行为不变。

## 回归测试要点

- 正常卡片导入全流程不变（路径校验、覆盖语义、规则补齐、checkpoint 回填）。
- ZIP 导入及其 32MB/5000 上限不受影响（角色卡闸门独立常量）。
- 工作区 header/full 档位渲染、file_cache 命中路径不变；仅超大文件走占位降级。
- stat 预检失败（权限/时序）时放行，core 层闸门兜底，不误伤正常导入。
