# 聊天记录查询页卡片化重设计 PRD

## 背景

聊天记录查询已支持关键词 + seq 编号区间筛选（`Iterations/chat-history-search-seq-range`），但页面形态不佳：mobile 表单（关键词行 + 编号行）固定常驻列表上方、占据空间；desktop 面板同为常驻两行。用户希望改成**可折叠卡片式表单**（参考智能体配置的卡片视觉风格）：表单可收起，把屏幕让给消息列表；长消息默认折叠、点击展开。

现状（探索确认）：mobile 的长消息折叠**已实现**（`MessageResultCard` 200 字/4 行截断 + 点击展开），保持即可；desktop 复用 `MessageList` 渲染结果，无任何折叠能力。项目可折叠先例为 real prompt 预览的 `PromptPreviewSegmentCard`（▶/▼ 切换、无动画）。

## 目标（含成功指标）

- 查询表单收进可折叠卡片：默认展开供输入，查询成功后自动收起；收起态以摘要行展示当前筛选条件
- 长消息折叠双端一致：mobile 保持既有行为，desktop 补齐
- 成功指标：表单收起后消息列表可视区域显著增大；收起态不点开也能看清当前筛选条件；折叠/展开无动画（用户拍板，与项目先例一致）

## 用户与场景

- mobile/desktop 用户在会话详情发起聊天记录查询，输入关键词/编号区间后浏览结果
- 用户想修改筛选条件时点开卡片表单重新查询

## 范围
### 包含范围
- mobile 查询页（ChatHistorySearchScreen）表单区改可折叠卡片
- desktop 查询面板（ChatHistorySearchPanel）表单区改可折叠卡片
- desktop 结果区长消息默认折叠、点击展开
- mobile 结果卡片折叠行为保持（可顺手统一 chevron 视觉，不强求）
- 收起态筛选摘要（如「关键词 "xx" · #10–50」，无筛选时显示默认文案）

### 不包含范围
- 折叠/展开动画（用户明确不要）
- 查询逻辑、分页、区间校验等行为变更（沿用 seq 迭代已交付能力）
- 桌面端 MessageList 组件本身的重构（仅在外层包折叠容器，具体由 spec 定）

## 核心需求（3-7 条）

1. **可折叠卡片表单（mobile）**：表单收进卡片容器，卡片头部（标题「筛选条件」+ 收起态摘要 + ▶/▼ chevron）点击切换展开/收起；展开态内为关键词、编号区间输入与查询按钮（沿用现有输入控件与 testID）
2. **可折叠卡片表单（desktop）**：同款交互与视觉（HTML/CSS 实现按 desktop 既有样式体系）
3. **默认展开、查询后自动收起**：进入页面表单默认展开；触发查询且成功返回结果后自动收起，把区域让给结果列表；无结果或校验错误（如区间倒挂）时不收起
4. **收起态摘要**：显示当前生效的筛选条件摘要；点击卡片可重新展开修改，修改后再查询
5. **desktop 长消息折叠**：结果中的长消息默认按行数截断折叠，点击展开/收起；阈值与 mobile 对齐（具体行数 spec 定）
6. **无动画**：所有折叠/展开均为直接显隐，不做过渡动画

## 验收标准

- Given 进入查询页 When 首次加载 Then 表单卡片默认展开，可输入关键词与编号区间
- Given 输入条件并查询成功 When 返回结果 Then 表单卡片自动收起，收起态摘要正确显示（关键词 + 区间）
- Given 查询无结果 / 区间倒挂校验失败 When 查询 Then 表单不收起，错误/空态提示可见
- Given 表单已收起 When 点击卡片头 Then 表单展开且保留上次输入值
- Given 表单已收起（mobile）When 下拉触底加载 Then 翻页仍携带当前筛选条件（含 seq 区间）
- Given desktop 结果中存在长消息 When 渲染 Then 长消息默认截断折叠，点击展开、再点收起
- Given mobile 结果卡片 When 点击 Then 展开/收起行为与现状一致（回归）
- Given 任意折叠/展开操作 Then 无过渡动画，即时切换
