# 文件名智能排序 PRD

## 背景

novel-master 的目录规则（workplace dir rule）目前提供三种排序方式：文件名称、创建时间、更新时间。其中「文件名称」是纯字典序比较，导致两类问题：

1. **序号类文件名乱序**：小说场景大量存在「第一章.txt、第二章.txt……第十章.txt」这类中文序号文件名，字典序下「第十章」排在「第一章」前面；「第2章」与「第10章」同理倒置。用户目前只能靠手动改名（补零）来纠正，成本高。
2. **目录排序与排序方式脱节**：子目录的排序目前只看升序/降序方向，无视所选排序方式，属于实现欠账。

参考项目 legado（阅读器）的 txt 目录规则体系（正则规则库 + 规则管理页）验证了「规则驱动的章节识别」是成熟做法，但其「命中数优选」机制面向整本书正文，不适用于逐个文件名的排序场景。本需求采用**优先级列表**模式改造：对每个文件名按优先级取第一条命中的规则提取序号。

另注：现状中「创建时间」与「更新时间」实际比较同一个时间戳，此问题不在本需求内修正，仅在此声明避免误解。

## 目标（含成功指标）

让选用了智能排序的目录里，「第X章」「第X卷」「Chapter N」「001」这类带序号的文件名**按人类直觉的顺序排列**，无需用户手动改名补零；同时用户可以像管理正则规则一样，自建、调整、共享智能排序规则。

成功指标：

- 「第一章～第十一章」连续中文序号文件名在智能排序下 100% 正确排列（含与阿拉伯数字混排）；
- 规则的增删改、启停、调序、导入导出操作后，重新进入目录即可看到新排序，无需重启应用；
- 未选用智能排序的目录，文件排序行为与现状完全一致（零回归）；时间排序（created/updated）下子目录序按需求 5 预期修复（从恒字典序改为按目录时间），不视为回归。

## 用户与场景

- **用户**：在 novel-master 中管理小说/文本文件的作者与读者，移动端（文件管理器）与桌面端（工作区树）双端使用；以及通过 CLI 验证能力的 agent。
- **场景 1**：导入一批「第一章.txt…第一百章.txt」的分章文件，打开目录发现顺序错乱，进入目录规则选「智能排序」，章节立即按顺序排列。
- **场景 2**：用户的文件名带卷章复合结构（「第X卷-第Y章」），内置规则不认识其变体，用户在设置里新增一条自定义正则、置顶，回目录即生效。
- **场景 3**：用户在多设备间同步规则，通过导出/导入 YAML 完成迁移。
- **场景 4**：agent 通过 CLI 的测试命令验证规则与排序行为，无需真实建目录放文件。

## 范围

### 包含范围

1. **排序方式新增「智能排序」**：目录规则的排序方式增加第四个选项，移动端规则面板、桌面端规则弹窗、CLI `--sort` 参数三端一致提供；相关 UI 分组文案由「排序字段」改为「排序方式」。
2. **智能排序比较器**（产品语义）：
   - 规则采用优先级列表：按用户可调的优先级顺序逐条尝试，第一条命中者负责提取序号；
   - 规则以正则表达式的**捕获组**提取序号，多个捕获组组成复合序号（如「卷-章」），逐位数值比较；
   - 中文数字（含大写）转换为数值后参与比较；
   - 命中序号的文件排在未命中文件之前（升序视角下章节文件在前、杂项沉底）；
   - 未命中任何规则的文件名走自然排序（数字块按数值比较，如 第2话.txt < 第10话.txt）；
   - 序号完全相同的文件按原文件名稳定排序；
   - 降序为整个顺序的严格反转。
3. **内置默认规则集**：随应用预置常用规则（建议集：「第X卷第Y章」卷章复合、中文「第X章/节/卷/回/集/部/篇」族、英文「Chapter/Section N」、数字序号开头），支持一键恢复默认；集内卷章复合规则优先于单序号规则（排列在前），避免「第X卷…第Y章」类文件名被单序号规则抢占、只提取到卷号。
4. **智能排序规则管理页**（设置内新增，移动端 + 桌面端）：
   - 列表：名称、示例说明、启用开关；
   - 单条：新增、编辑（名称/正则/示例）、删除（带确认；内置规则除外，仅可禁用）、正则语法校验；
   - 排序：上移/下移、拖拽调序；
   - 批量：批量启用/禁用、批量删除；
   - 导入/导出：YAML 格式；
   - 恢复默认规则（不影响用户自建规则）；
   - 编辑/测试预览：输入示例文件名，实时查看每行命中的规则与提取出的序号。
5. **目录按排序方式排序**：目录规则所选排序方式同时作用于子目录排序（含智能排序），修复「目录只看方向不看方式」的欠账。
6. **CLI 支持**：规则管理命令（列表/增删改/启停/调序）与排序测试命令（输入文件名列表，输出排序结果及每行命中的规则与序号），定位为 agent 自测工具，从简实现。

### 不包含范围

- 跨目录层级的序号组合（「卷」在目录名、「章」在文件名的拼接比较）——各目录层级规则独立生效，天然不需要；
- 规则的在线导入/规则市场；
- VFS 树、聊天附件树等其他独立字典序链路的改造；
- 「创建时间/更新时间」比较同一时间戳的语义问题（另立需求）；
- 规则的「命中数优选」等自动裁决机制（明确采用优先级列表，不做优选）。

## 核心需求

1. **排序方式扩展**：目录规则可选「智能排序」，三端（mobile/desktop/CLI）一致，UI 文案同步调整为「排序方式」。
2. **智能排序行为**：优先级列表 + 捕获组序号（含复合序号）+ 中文数字转换 + 有序号优先 + 自然排序回退 + 文件名稳定 tiebreak + 降序严格反转。
3. **内置规则集**：预置常用序号识别规则，可恢复默认，默认规则与用户规则隔离管理。
4. **规则管理页**：双端完整的规则管理功能面（列表/启停/增删改/上下移/拖拽/批量操作/YAML 导入导出/测试预览/恢复默认）。
5. **目录排序修复**：排序方式（含智能排序）对子目录同样生效。
6. **CLI 能力面**：规则 CRUD 与排序测试命令，输出可机器解析。

## 验收标准

**排序正确性**

- [ ] Given 目录内文件 [第十一章, 第十章, 第二章, 第一章, 第2章]，When 选智能排序升序，Then 顺序为 第一章、第2章、第二章、第十章、第十一章（序号相同者如「第2章/第二章」按原文件名稳定排列，不随机）。
- [ ] Given 文件 [第1卷-第3章, 第1卷-第5章, 第2卷-第1章]，Then 复合序号按卷优先、章次之排列。
- [ ] Given 文件 [2.txt, 10.txt, 1.txt]，Then 排序为 1.txt、2.txt、10.txt（数字按数值比较而非字典序）。
- [ ] Given 全部未命中序号规则的文件 [公告.txt, 作者的话.txt, 封面.txt]，Then 按自然排序为 作者的话.txt、公告.txt、封面.txt（未命中回退自然排序）。
- [ ] Given 目录内混有 [封面.txt, 第一章.txt, 公告.txt]，升序时第一章在前、封面与公告按自然排序沉底；降序时整个顺序严格反转。
- [ ] Given 子目录 [第一卷, 第三卷, 第十卷]，When 父目录选智能排序，Then 子目录按卷序排列。
- [ ] Given 目录未选智能排序（如默认名称升序），Then 排序结果与当前版本完全一致。

**规则管理**

- [ ] 新增一条自定义规则并置顶后，被其命中的文件名按新规则提取序号，优先于内置规则。
- [ ] 禁用某内置规则后，该规则不再参与匹配。
- [ ] 内置规则仅可禁用、不可删除；禁用状态在应用重启后保持。
- [ ] 拖拽与上移/下移调整优先级后，重新进入目录排序随之变化。
- [ ] 批量禁用/删除选中规则生效。
- [ ] 导出的 YAML 再导入后规则集一致（round-trip 无损）。
- [ ] 恢复默认只重置内置规则，用户自建规则不受影响。
- [ ] 编辑规则时输入非法正则被拦截并提示；测试预览能显示每行示例文件名命中的规则与提取序号。

**CLI**

- [ ] `sort-rule` 管理命令可完成列表/增删改/启停/调序；
- [ ] 测试命令输入文件名列表，输出排序后顺序 + 每行命中的规则名与序号，格式可解析。

**兼容性**

- [ ] 存量用户升级后，未改设置的目录：文件排序行为与现状完全一致；name 排序下子目录序零回归；时间排序（created/updated）下子目录序按需求 5 新语义生效（从恒字典序改为按目录时间，属预期修复而非回归）；已保存的目录规则（名称/时间排序）不丢失，文件排序语义不变。
