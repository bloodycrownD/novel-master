# 导入目录规则默认开启（角色卡 + ZIP）PRD

## 背景

mobile 用户在文件管理中导入角色卡后，导入出来的目录在列表里显示为目录规则「关闭」状态，要进出一次文件夹才会变成「开启」。根因有两层：其一，目录规则的口径是「无规则行 = 关闭」，而导入链路本身不保证给新增目录写入默认启用规则行，补行的动作由 mobile UI 层在导入完成后自行执行；其二，UI 层补行发生在列表刷新之后，刷新那一刻规则行还没落库，列表显示的是「关闭」，补行后又没有第二次刷新。此外，UI 层补行只覆盖一层子目录，嵌套更深的目录会漏补。

ZIP 导入与角色卡导入在 mobile 侧共用同一套补行逻辑，存在完全相同的问题。desktop 端的导入路径甚至完全没有补行，导入出来的目录落库即为关闭。

业务上「导入产生的目录默认参与文件树裁剪（默认开启）」是既有口径（与 agent 写文件、新建目录时的默认行为一致），当前问题是这个口径的保证分散、不完整、且依赖 UI 时序。

## 目标（含成功指标）

导入（角色卡 / ZIP）完成后，所有新增目录——包括任意深度的嵌套子目录——立即且持久地处于目录规则「开启」状态；文件管理列表无需进出文件夹即可正确显示；两条导入路径行为完全一致。

成功指标：

- 导入后不进行任何导航操作，列表中全部新增目录均显示「开启」。
- 含多层嵌套目录的角色卡 / ZIP 导入，嵌套目录同样默认开启。
- 角色卡导入与 ZIP 导入在上述行为上无差异。

## 用户与场景

- 用户：使用 mobile 文件管理功能、通过角色卡或 ZIP 导入内容的会话使用者。
- 场景一：用户在文件管理某目录下导入一张角色卡（角色卡解出若干嵌套目录与文件），期望导入完成回到列表时，这些目录已按默认规则参与文件树，无需手动逐个开启。
- 场景二：用户导入一个 ZIP 包，期望与角色卡导入得到完全一致的结果。
- 场景三：用户导入后立即查看列表开关状态，所见即所得，无需通过进出文件夹「触发刷新」才能看到正确状态。

## 范围

### 包含范围

- mobile 端角色卡导入、ZIP 导入（各 scope 均适用）。
- 「导入产生的所有新增目录（含嵌套）默认开启目录规则」作为统一业务口径，由导入链路本身保证，不再依赖各端 UI 自行补行。
- 导入完成后 mobile 文件管理列表立即呈现正确状态。
- 导入链路统一保证后，desktop 导入路径因走同一链路自然获得同口径（desktop UI 侧的其它刷新问题不在本次范围）。

### 不包含范围

- 已存在目录的规则状态调整（只管导入新增的目录）。
- 用户显式关闭某目录规则后的行为（导入不覆盖用户已有设置；本次只处理「新增目录」）。
- desktop UI 侧导入后的事件广播 / 刷新问题。
- 导入缓存对齐（rule_snapshot + file_cache 清理）行为——已有独立口径，维持现状。

## 核心需求（3-7 条）

1. 导入（角色卡 / ZIP）产生的所有新增目录，无论层级深度，默认处于目录规则「开启」状态。
2. 该保证由导入链路统一提供，双端导入入口共享同一口径，mobile 不再依赖 UI 层自行补行。
3. 导入完成后，mobile 文件管理列表立即显示正确的规则开启状态，无需用户进出文件夹或手动刷新。
4. 单个目录的规则写入失败不阻断整体导入流程（沿用现有容错口径）。
5. 导入前后规则行已存在（含显式关闭）的目录不受影响——导入只对新增目录补默认启用，不覆盖已有设置。

## 验收标准

- Given 一个含多层嵌套目录的角色卡，When 用户在 mobile 文件管理中导入成功，Then 不进行任何导航，列表中该角色卡产生的全部目录（含嵌套）均显示「开启」。
- Given 一个含嵌套目录的 ZIP 包，When 用户导入成功，Then 行为与角色卡导入完全一致（全部新增目录「开启」、列表即时正确显示）。
- Given 导入的目标目录下已存在同名目录且其规则被用户显式关闭，When 导入完成，Then 该既有目录的关闭状态不被改变。
- Given 导入过程中个别目录的规则写入失败，When 导入流程结束，Then 导入本身仍报告成功，且其余目录的规则状态不受影响。
- Given 导入完成后的会话，When 下一轮提示词拼装时，Then 导入目录按开启规则正常参与文件树裁剪（不因缺规则行被排除）。
