# Mobile/Desktop 体验优化与修复（2026-08）PRD

## 背景

本迭代源于一次深度的 mobile 端使用测试，过程中发现了一系列影响体验的问题，覆盖子会话、智能体配置、UI 交互、核心 bug 等多个层面。这些问题在 desktop 端经代码审查同样存在（或存在对应隐患），因此本次迭代决定双端同步修复。

探索阶段已对全部问题的根因、改动面、关键证据做了完整摸排（见各 feature 的 PRD/SPEC），此处仅做总纲性说明：

- **子会话工作区**当前完全复用父会话的 VFS/KKV 缓存，导致子会话加载的工作区内容与其提示词上下文不一致（子会话没有工具调用历史，却加载了父会话的工作区快照）
- **智能体配置**层面，`customAttach`（extra info）对所有 user 消息都注入同一份内容，历史消息也注入，浪费且语义不准；项目智能体功能使用率低且让智能体选择变复杂
- **UI 交互**方面，工具配置 picker 在手机上展开后无法收起且样式原始；子会话结束后「生成中」标识残留；服务商配置入口分散（独立「编辑」菜单项），缺少 tab 化整合
- **核心 bug** 包括：子会话 write/edit 卡片跳转异常、edit 工具对中文引号匹配失败、批注消息（只有批注、无文字）无法回滚且绕过连续 user 阻塞守卫

## 目标（含成功指标）

**目标**：一次性消除本次测试发现的全部 mobile 端痛点，并在 desktop 端对照修复同类问题，使双端在受影响功能上行为一致。

**成功指标**：

1. 各 feature 验收标准全部通过（可测试、可判定）
2. mobile/desktop 在受影响功能上行为一致（双端对照测试无差异）
3. 现有自动化测试无回归
4. 用户（重度使用者）主观体验明显改善，尤其是子会话工作区一致性、批注消息可回滚性、工具配置 picker 的手机友好度

## 用户与场景

**目标用户**：重度使用者——长会话、子智能体、批注、文件操作、自定义智能体配置都在用的人。这类用户对一致性和边界行为敏感，容易踩到普通用户碰不到的坑。

**典型场景**：

- 在长会话中派发子智能体处理子任务，期望子智能体有独立的工作上下文而非继承父会话的全部工作区
- 用批注功能给文件片段加注后直接发送（不带正文文字），期望能撤销发送
- 在手机上配置智能体的工具白名单，期望 picker 能收起、样式友好
- 配置服务商时，期望在服务商详情页内就能切换编辑连接配置与管理模型
- 编辑含中文引号的文件时，期望 edit 工具能正确匹配

## 范围

### 包含范围

本迭代下分 4 个 feature，各有独立 PRD/SPEC：

| Feature | 主题 | 包含问题 |
|---------|------|---------|
| **A. 子会话工作区隔离** | 子会话用自己 sessionId 从空产生常驻工作区 | 原问题 7 |
| **B. 智能体配置精简** | extra info 只最新消息拼接 + 移除项目智能体 | 原问题 4、5 |
| **C. UI 优化** | 工具 picker sheet 化 + 生成中兜底 + 服务商 tab | 原问题 2、6、8 |
| **D. bug 修复** | write/edit 跳转 + edit 引号归一化 + 批注消息回滚 | 原问题 1、3、9 |

每个 feature 的详细范围、需求、验收标准见各自 `features/<feature>/prd.md`。

### 不包含范围

- **desktop 端的新功能/UI 重构**：desktop 本次只对照修复 mobile 发现的问题及代码审查确认的同类隐患，不做 desktop 独有的新功能或大规模 UI 重构
- **性能优化**：除非是 bug 修复的副产物，否则不主动做性能调优
- **新能力开发**：不引入本次测试范围外的新需求

## 核心需求（总纲级）

1. **子会话工作区隔离**：子会话用自己 sessionId 从空产生常驻工作区内容，不再加载父会话工作区缓存，避免「加载的工作区内容与提示词上下文不一致」
2. **extra info 只最新消息拼接**：`customAttach` 的 `<extra-info>` 块只注入最新一条 user 消息，历史消息不再注入（与 dynamic 区 once 语义不同，独立实现）
3. **移除项目智能体**：删除项目级内联智能体定义能力（follow/custom），所有项目统一走 session 级智能体选择
4. **工具配置 picker 手机友好化**：picker 改为 trigger + 底部 sheet 多选，支持收起，样式对齐同表单的 FormSelectField
5. **子会话「生成中」兜底**：为子会话的 uiRunning 状态加兜底机制（轮询/visibilitychange），避免事件丢失导致「生成中」永久残留
6. **服务商配置 tab 化**：服务商详情页加两个 tab（服务商配置 + 模型管理），移除独立的「编辑」菜单项
7. **核心 bug 修复**：write/edit 卡片跳转、edit 中文引号归一化、批注消息回滚与连续 user 守卫

## 验收标准（总纲级）

每个 feature 有独立验收标准，此处仅列迭代级门槛：

- [ ] 4 个 feature 的 prd.md 与 spec.md 全部落盘并经用户确认
- [ ] 所有 blocking 测试用例通过
- [ ] mobile/desktop 双端对照测试，受影响功能行为一致
- [ ] 现有自动化测试套件无回归
- [ ] CHANGELOG 按版本记录本次迭代变更

## 约束与依赖

- **双端一致性**：mobile/desktop 共用 core 层的部分逻辑（如 customAttach 拼接、回滚判定、edit 匹配），改动 core 层时须保证双端同步受益
- **向后兼容**：移除项目智能体涉及 DB 列（`chat_project.agent_config_json`）与已有数据，需提供迁移策略
- **desktop 对照修复**：desktop 端未经实测，修复依据是代码审查，可能存在 mobile 未暴露的额外问题或相反情况

## 风险与待确认项

- **desktop 测试覆盖**：desktop 端本次只做对照修复，未经实测，可能漏修或改出新的不一致——合并后需用户在 desktop 上做一轮验收
- **子会话工作区隔离的产品边界**：从空开始意味着子智能体看不到父会话的文件上下文，需确认这是期望行为（探索阶段用户已确认「从空开始」）
- **edit 引号归一化的字符族覆盖范围**：弯引号↔直引号、「」『』↔""''、全角/半角空白等，具体覆盖哪些字符族需在 spec 中明确并补测试
