# 多会话并行 + 后台保持请求 + 完成通知 PRD

## 背景

mobile 当前是「全局单 run」模式：任意时刻整个 app 只允许一个进行中的生成，用户在别的会话想同时发起时会被静默拦截、没有任何反馈。同时，生成中的请求与用户停留在会话页强绑定——app 退到后台、锁屏或切走其它 app 后，进行中的请求会失败（代码中并不存在「离开页面即中断」的逻辑，失败根因指向系统对后台化应用的网络限制）。此外 app 没有任何通知能力，用户离开页面后无从得知生成何时结束。

项目内已有可复用的基础：core 层的会话隔离机制（按会话独立的注册表）天然支持多 run 并存；子会话页已有「重进探测进行中 run」的先例；主会话流式重进恢复已单独立项（本 PRD 依赖其恢复机制）。

## 目标（含成功指标）

- **多会话并行**：不同会话可同时各有一个进行中的生成，互不阻塞、互不串扰。
- **后台保持**：除用户主动关闭应用外，生成不因退后台、锁屏、切换其它 app 而中断。
- **完成通知**：生成结束时发送本地通知，用户可点按直达对应会话；通知可在设置中开启或关闭。

成功指标：

- 两个及以上会话同时生成，各自完整落库、内容正确无串扰。
- 长生成期间切走 app 超过 5 分钟后返回（应用未被关闭），生成仍在进行或已正常完成。
- app 在后台期间生成结束，用户收到通知并可一键回到对应会话。

## 用户与场景

- 用户：使用 mobile 与 agent 进行长对话的用户；典型生成耗时数十秒到数分钟。
- 场景一：用户在会话 A 发起生成，随即切到会话 B 继续聊并也发起生成，两边同时跑，各自完成后都能看到完整结果。
- 场景二：用户发起生成后切去别的 app 或锁屏，稍后收到「生成完成」通知，点按回到会话看到结果。
- 场景三：用户觉得通知打扰，在设置里关掉，之后生成结束不再收到通知（生成本身不受影响）。

## 范围

### 包含范围

- mobile 端跨会话并行：每个会话同时最多一个进行中的 run，跨会话数量不限。（并行与 app 内保持天然跨平台；后台保活与通知验收以 Android 为准，iOS 本次不承诺）
- 后台保持：退后台、锁屏、切换 app 期间请求继续，直到回合结束；仅用户主动关闭应用（杀进程）时终止。
- 生成结束的本地通知：成功与失败均可通知，点按直达对应会话；设置中提供开关。
- Android 13+ 通知权限的申请与引导。
- 回页 / 回前台的运行状态与流式进度恢复（复用主会话流式恢复的机制）。
- 既有保护口径保留：任意 run 活跃期间不触发备份 / 云同步。

### 不包含范围

- 应用被杀 / 崩溃后的 run 恢复（app 关闭即终止，仅已落库内容存活）。
- 同一会话内的并行（单会话内维持一次一个 run，重复发起沿用现有行为）。
- 远程推送通知（仅本地通知，不依赖服务端）。
- desktop 端（本次聚焦 mobile）。
- 轮数上限导致「生成中」状态残留的修复（独立问题，另行处理）。
- 「生成中」状态的兜底探针等既有 UI 状态问题（可顺带实现，不作为本需求验收项）。

## 核心需求（3-7 条）

1. 跨会话并行：移除「全局同时仅一个 run」的限制；任一会话能否发起新生成，只取决于该会话自身是否有进行中的 run。
2. 后台保持：生成进行期间 app 可退后台 / 锁屏 / 切换而不中断请求（含必要的前台保活手段及其系统要求的通知形态）。
3. 完成通知：run 结束（成功或失败）时发送本地通知，通知点按直达对应会话；app 在前台（任意页面，含生成中的会话界面）时不发、仅后台时发（避免前台打扰；此为默认口径，用户确认 spec 时可推翻）。
4. 通知开关：设置中新增「生成结束通知」开关，关闭后仅不再通知，生成与后台保持行为不变。
5. 回页恢复：从其它会话、其它页面或后台回到生成中的会话，运行状态与流式进度正确恢复（体验与主会话流式恢复一致）。
6. 既有守卫不回退：备份 / 云同步在任意 run 活跃期间不被触发。

## 验收标准

- Given 会话 A 生成中，When 用户在会话 B 发起生成，Then B 正常开始并运行，A 不受影响，两者各自完整落库。
- Given 会话 A 生成中，When 用户在会话 A 再次发送消息，Then 维持现有单会话行为（不产生同会话并行）。
- Given 会话 A 刚发起生成（已受理、流式尚未开始），When 用户切到会话 B 再切回 A，Then 运行状态正确恢复、迟到的流式启动事件被接纳反填、进度不丢失。
- Given 会话 A 刚发起生成（已受理、流式尚未开始），When 用户在会话 A 再次发送消息，Then 被拒绝（不因注册时延产生同会话双 run）。
- Given 长生成进行中，When 用户切走 app 并锁屏 5 分钟后返回（应用未被系统外力关闭），Then 生成仍在进行或已正常完成，进度无丢失。
- Given app 在后台期间生成结束，When 通知到达，Then 用户点按通知直达对应会话并看到完整结果。
- Given app 在前台（停留在任意页面，含生成中的会话界面），When 生成结束，Then 不发送本地通知（前台界面自有完成反馈）；仅 app 在后台期间生成结束时发送。
- Given 设置中关闭「生成结束通知」，When 后台期间生成结束，Then 不再收到通知，生成与后台保持行为不变。
- Given 任意 run 活跃期间，Then 备份 / 云同步不被触发（守卫口径不回退）。
- Given 用户主动关闭应用，When 重新打开进入原会话，Then run 已终止、无「生成中」残留，已落库内容完整。

## 约束与依赖

- 依赖主会话流式重进恢复（`Iterations/main-session-stream-resume/prd.md`）的回页恢复机制。
- Android 前台保活需遵守系统约束：前台服务需展示常驻通知；Android 14+ 对 `dataSync` 前台服务有约 6 小时系统上限，超时后服务被系统停止，按「应用被外力关闭」口径处理（不在承诺内）；Android 13+ 通知需 `POST_NOTIFICATIONS` 运行时权限（申请时机钉死为首次发起 run 且开关为开时；拒绝时保活照常、仅无完成通知）。

## 非功能需求（业务/体验）

- 后台保活的常驻通知文案应清晰说明「正在生成」，避免用户误认为异常。
- 多会话并行时各会话的流式互不串扰，事件按会话正确路由。

## 风险与待确认项

- 通知开关默认值：暂定默认开启（用户主动要求的能力），可在实现评审时复核。
- 通知权限被拒绝时（已定口径）：前台保活照常（服务继续，系统层可能不展示常驻通知）、完成通知不发、不重复申请。
- 失败通知的文案与噪音控制（频繁失败是否合并 / 抑制）待定。
- 各厂商 ROM 的后台限制差异（省电策略强杀）无法完全规避，验收以「应用未被外力关闭」为前提。
