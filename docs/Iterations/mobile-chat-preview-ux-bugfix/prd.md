# Mobile 聊天与预览体验修复 PRD

## 背景

两个 mobile 端已确认的行为缺陷，影响用户对基础功能的信任：

1. **会话改名不生效（表象）**：在会话详情页行内改名并保存成功（toast 提示「已重命名」，数据库实际已更新），但返回聊天页后顶栏标题与会话列表仍显示旧名称，需重启应用或切换项目才能看到新名。列表入口的改名不受影响，仅详情页路径存在该问题。
2. **文件预览·文本模式无法复制**：文件预览切换到「文本」标签后，长按正文无任何反应，无法选择、复制内容；markdown 模式无此问题。移动端用户无法把预览中的文本带走。

## 目标（含成功指标）

- 详情页改名后，所有展示会话名称的位置即时反映新名称。
- 文本模式正文可通过长按选择并复制。

成功指标：两个缺陷的复现路径在修复后均无法复现；不引入新的刷新闪烁或复制误触问题。

## 用户与场景

- 用户在详情页把会话从默认名改成有意义的名字，返回聊天页继续对话，期望立刻看到新名字。
- 用户在文本模式查看配置 / 笔记文件，需要复制一段内容到别处（聊天输入框、其他应用）。

## 范围

### 包含范围

- mobile 会话详情页改名路径的名称同步：聊天页顶栏标题、会话列表、列表改名入口的初始值。
- mobile 文件预览「文本」标签：正文支持长按选择、复制。
- 复制来源为用户可见的正文内容（含 Front Matter 原文，与该标签「显示完整源码」的既有语义一致）。

### 不包含范围

- desktop 端（desktop 改名链路与文本选择均正常）。
- markdown 渲染模式的复制交互（WebView 内已有既有行为，不动）。
- 自定义选择浮层 /「复制」菜单按钮等增强交互（如系统原生选择能力可用，即满足需求）。
- 会话重命名的其他入口与批量改名。

## 核心需求（3-7 条）

1. **改名即时同步**：详情页改名保存成功后，返回聊天页时顶栏标题与会话列表立即显示新名称，无需重启、无需切换项目。
2. **列表入口一致**：从列表改名入口再次打开改名时，初始值为最新名称（不出现旧名回填）。
3. **文本可选择**：文本模式正文长按可进入系统文本选择状态，可通过系统复制能力复制选中内容。
4. **复制内容正确**：复制到剪贴板的内容与所选择的正文文本一致（不串行、不含 UI 杂质）。
5. **不影响既有交互**：文本模式的滚动浏览、markdown 模式的行为均与现状一致。

## 验收标准

| # | Given / When / Then |
|---|---|
| 1 | Given 任意会话；When 在详情页改名保存成功；And 返回聊天页；Then 顶栏标题显示新名称。 |
| 2 | Given 同一场景；When 查看会话列表；Then 该会话行显示新名称。 |
| 3 | Given 已通过详情页改名的会话；When 从列表改名入口再次发起改名；Then 输入框初始值为最新名称。 |
| 4 | Given 改名后未重启应用；When 杀掉应用重新进入；Then 名称保持一致（持久化正确，无回退）。 |
| 5 | Given 文本模式打开任一非空文件；When 长按正文任意文字；Then 进入文本选择状态（出现选择锚点 / 系统菜单）。 |
| 6 | Given 已选中一段文字；When 执行复制并粘贴到聊天输入框；Then 粘贴内容与所选文字一致。 |
| 7 | Given 空文件或纯空白文件；When 预览文本模式；Then 显示既有「（空文件）」占位，长按无异常。 |
| 8 | Given 文本模式滚动浏览长文件；When 正常滑动；Then 滚动行为与现状一致，长按选择不误触发。 |
