# 会话流式单元（真并发重构）PRD

## 背景

mobile 端的聊天流式链路目前是「单槽换绑」模型：ChatTabProvider 持有**唯一一套**运行态（uiRunning、activeRunId、流式缓冲、注入标记、恢复窗口、freeze/retain），会话切换时整体 reset、重进时靠多条时序敏感的重建链（探针合成、恢复注入、backfill）模拟 per-session 语义。多会话并行（含子代理子会话）成为正式能力后，这条缝隙持续产出并发 bug：

- 串会话消息（旧会话异步结果灌进新会话屏幕，重启才恢复）；
- 后台收尾会话的消息丢失渲染（重进水合旧缓存）；
- 调用 subagent 期间父会话消息不显示、终止后才渲染；
- 统计条串号（显示别的会话字数）与重进从零计时；
- 任务卡映射切换会话即清空、灰置不可点；
- 历史上多轮修复的【生成中】残留、agentActive 泄漏等。

每一轮修复都在收窄某一条路径，但换绑这个结构性缝隙会持续生成新的时序排列。四路探索确认：Manager、流式指标 store、消息视图缓存等已按 sessionId 键控并与展示解耦（方向正确），真正的问题集中在——屏幕单槽的运行态、切走后事件消费者蒸发、收尾路径多头、partial 注入三份拷贝、子会话屏双装配。

用户拍板：**重设计为真并发模型，一步到位（含运行态持久化），直接替换旧链路不留灰度**（C 端回滚靠 git）。

## 目标（含成功指标）

1. **真并发**：任意多个会话（同项目/跨项目/子代理子会话）可同时生成，互不干扰；切换会话 = 纯换镜头，零状态迁移。
2. **可恢复**：运行态（进行中的 partial、指标、运行标记、子会话链接）持久化到会话；app 被杀后重进可看到中断现场。
3. **可维护**：重建路径（恢复窗口、探针合成、重进注入、发起保护窗）从「多条时序敏感链」收敛为「单元从未销毁，无需重建」。

成功指标：
- 本迭代踩过的全部并发 bug 以验收用例形式全灭（见验收标准清单）；
- 单会话（无并行）行为与现状逐项一致——现有回归套件全绿；
- 流式链装配点收敛：主会话与子会话共用同一套单元抽象，partial 注入只剩一份实现。

## 用户与场景

- **并行写作者**：同时开多个会话让模型分头生成（不同项目、不同章节、主线+子代理任务），在会话间快速切换查看进度。
- **挂机等待者**：发起生成后切走/退后台，靠状态栏通知知道进度，回来要看到**完整且最新**的画面（含后台已收尾的消息）。
- **子代理使用者**：主会话派 task 给子代理，期间要在父会话看到任务卡并可点进子会话浏览；嵌套子会话同理。
- **意外中断者**：生成中 app 被杀/崩溃，重进后能看到已生成的部分与「已中断」状态，而不是凭空消失。

## 范围

### 包含范围
- 按 sessionId 键控的会话流式单元：事件订阅、lifecycle/abort、消息管线、流缓冲与注入、指标、子会话链接，全部随会话而非屏幕。
- 跨项目并行：单元以会话为最细粒度，项目只是属性，无项目级耦合。
- 运行态持久化（写通 + 重启水合）：进行中 partial、指标、运行标记、pending 子会话链接；语义上属会话数据而非可丢缓存（fork/copy 不复制、置位/压缩不清运行态字段需明确定义）。
- 子会话屏（SubagentSessionScreen）并入同一单元抽象，消除双装配。
- 停止操作面向会话而非屏幕：前台停止维持；后台会话获得停止入口（会话列表操作项；通知栏聚合通知维持现状不带停止）。
- webview 渲染面（ChatTranscriptWebView 契约、可见性脏重挂）作为哑引擎保留，驱动侧改接单元。

### 不包含范围
- 多屏同显（设备单屏，同一时刻一个可见 webview 即可；单元需支持多订阅者但渲染面单槽）。
- legacy MessageList（非 webview 引擎）路径的迁移——维持现状不动。
- 桌面端（desktop）的对应改造。
- 生成内容的自动续跑（重启后仅展示中断现场，不自动恢复执行）。

## 核心需求

1. **会话流式单元**：run 开始时创建（或复用）、结束+宽限后销毁的独立对象，拥有该会话 run 的完整管线；屏幕（聊天 tab、子会话屏）退化为纯订阅者——订阅单元投影、注册自己的 webview 句柄，切换/退出只做订阅增减。
2. **后台会话不蒸发**：切走的会话其单元继续消费事件——流式显示、step 级消息落库跟进、视图缓存刷新、收尾提交照常发生；重进任意会话看到的一律是最新状态，无「等 run 结束才渲染」窗口。
3. **运行态持久化与水合**：单元将派生状态节流写通到会话级持久层；进程重启后按会话水合——进行中的 run 呈现为「已中断」终态，已生成 partial 作为可读内容展示，指标与子会话链接恢复；正常结束的 run 其终态（上次生成）跨重启可见。
4. **指标按会话归属**（语义沿用既有拍板）：新 run 开始才重置；结束冻结为该会话「上次生成」；切会话/重进只换数据源；重进运行中会话显示真实连续历时。
5. **子会话统一**：子会话屏消费同一单元抽象与同一注入实现；pending 任务卡映射全局化——任何屏（含子会话屏内嵌套任务卡）在 run 期间可点进对应子会话。
6. **单会话零回归**：无并行场景下，所有既有行为（含本迭代已修复项）保持一致；现有测试套件作为替换的门禁。
7. **旧链路直接移除**：换绑 reset/探针合成/恢复注入等重建路径随单元化一并退役（其守护测试改写为单元级等价断言），不留双轨。

## 验收标准

并行压测（真机，每条都必须可复现地通过）：
- Given 双会话 A/B 并行生成中 When 快速来回切换多次 Then 任何时刻各屏只显示本会话内容（无串会话消息）。
- Given A 后台收尾完成 When 重进 A Then 最终消息立即可见（无丢失、无需重启）。
- Given A 调用子代理（长任务）When 停留/切走再回来 Then 任务卡可见且可点进子会话；父会话不出现「消息不显示直到终止」。
- Given A 运行中 When 切走再切回 Then 统计条历时连续（不从零）、字数仅本会话。
- Given 并行中 When 逐个停止各会话 Then 各自收尾互不影响；全部停止后无残留「生成中」。
- Given 生成中 app 被杀 When 重进该会话 Then 已生成 partial 可读、状态为「已中断」、指标与任务卡链接恢复。
- Given 跨项目两会话并行 When 交替查看 Then 行为与同项目并行完全一致。

单会话回归：
- 现有 mobile 相关回归套件全绿（含 composer、lifecycle、webview、指标、通知各套件）。
- 单会话完整对话流（发起/流式/工具/子代理/停止/完成通知/重进）与现状一致。

结构验收：
- partial 注入实现只剩一份（主会话与子会话共用）。
- ChatTabProvider 不再持有任何会话运行态（仅剩装配与路由）。

## 约束与依赖

- 依赖 agent-run-parallel-and-notify 迭代的既有基建（Manager/store/守卫成为单元内部件）。
- 持久层落在 core schema 时须遵守 SCHEMA_BOOT_VERSION 机制（技术选型在 spec 阶段定）。
- 替换需在 notify 分支上完成并全绿后才视为立住。

## 风险与待确认项

1. **后台停止入口形态**：会话列表操作项（长按/swipe）具体交互待拍板（默认：列表项操作组加「停止生成」）。
2. **中断现场展示语义**：「已中断」终态的视觉形态、partial 以何种样式呈现（默认：partial 作为只读 assistant 内容 + 中断徽标，不做续跑）。
3. **写通频率**：节流间隔与「被杀丢多少」的取舍（默认 250-500ms 合并，spec 阶段定）。
4. **单元宽限期**：run 结束后单元存活多久以服务「上次生成」展示（默认：跟随会话视图缓存既有 LRU 语义，spec 定）。
5. **同会话双屏并发**（主会话屏 + 子会话屏同时可见于导航栈）下 webview 句柄多路分发的细节（spec 定）。
