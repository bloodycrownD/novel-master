# thinking 进入上下文开关 PRD

## 背景

assistant 回复中的思考内容（thinking 块）目前**落库但是否进入下一轮提示词完全由协议决定**：anthropic / gemini 会把**全部历史轮次**的 thinking 块（含签名）回传进上下文，openai 则全部过滤。用户没有任何控制手段。

对照 Anthropic 官方文档核实：保留历史 thinking 的收益主要是工具循环的缓存命中优化，对模型表现无负面影响但也无必要；旧模型服务端会自动剥离历史 thinking；**跨模型切换时残留的无签名 thinking 块会触发 400 错误**（官方建议切换模型时主动剥离）。

用户拍板：新增**「思考内容进入上下文」开关，放在聊天设置**（全局级，与流式输出同层）；开启时**仅最新一轮**（最后一条用户消息之后的所有 assistant 轮次，含工具循环）的 thinking 进入上下文，历史轮次一律剥离；关闭时全部剥离（工具循环内协议强制保留的最新轮除外）。长对话创作场景上下文敏感，剥离历史思考是既省上下文又不损失效果的做法。

## 目标（含成功指标）

| 目标 | 成功指标 |
|------|----------|
| 用户可控 | 双端聊天设置新增开关；默认**开**（延续「思考参与上下文」的现状语义） |
| 语义明确 | 开=仅最新一轮 thinking 进上下文；关=全部不进（协议强制的工具循环最新轮除外） |
| 上下文节省 | 开启状态下，历史轮次 thinking 不再占用上下文（对比现状全量透传） |
| 稳定性提升 | 跨模型/协议切换会话时，不再因历史无签名 thinking 触发服务商 400 |
| 预览一致 | 「查看提示词」面板与实际发送口径一致：开关开时可见最新轮 thinking |

## 用户与场景

| 用户 | 场景 |
|------|------|
| 长对话创作者 | 数百轮的小说打磨对话中，历史思考不再挤占上下文预算，关键正文留存更久 |
| 省钱敏感用户 | 关闭开关后 thinking 完全不进上下文，token 开销下降 |
| 换模型用户 | 会话中途从 GLM 切到 Claude，历史 thinking 被剥离，请求不再报错 |
| 调试用户 | 「查看提示词」所见即所发，不再出现预览与实际口径分裂 |

## 范围
### 包含范围
- 双端聊天设置（desktop 设置→常规→聊天偏好；mobile 我的→聊天配置）新增全局开关
- 提示词拼装按开关剥离/保留 thinking（最新一轮语义）
- 「查看提示词」预览口径与实际发送同步
- 跨协议历史 thinking 的剥离保护

### 不包含范围
- 会话级粒度开关（本期全局级，会话级待用户反馈后评估）
- openai 协议的 thinking 注入（openai 出站本就过滤 thinking，开关不改变其行为；无论开关状态，openai 协议请求不含 thinking 内容）
- UI 展示层调整（聊天界面的思考过程折叠卡片维持现状）
- 服务商侧上下文编辑策略（如 Anthropic clear_thinking context-editing）对接

## 核心需求（3-7 条）

1. **全局开关**：聊天设置新增「思考内容进入上下文」开关，默认开；双端同名同语义，持久化于全局偏好。
2. **开启语义（仅最新一轮）**：开启时，仅最后一条用户消息之后的 assistant 轮次（含工具循环内全部 assistant 消息）的 thinking 块进入提示词；更早轮次的 thinking 与 redacted_thinking 一律剥离。
3. **关闭语义（全剥离）**：关闭时所有 thinking 不进提示词；但工具循环内最新 assistant 轮的 thinking 若协议强制要求保留（anthropic 签名配对约束），则按协议最低要求保留，且该保留不向用户暴露。
4. **完整回传约束**：进入提示词的 thinking 块必须原样（含签名、含 redacted_thinking）回传，不重排不删改，满足服务商校验。
5. **预览同步**：「查看提示词」面板按开关状态展示 thinking 内容（开=可见最新轮 thinking）。
6. **双端一致**：同一账号双端开关状态一致（读同一全局偏好）。

## 验收标准

- Given 开关开启且会话有多轮历史，When 发起请求，Then 提示词中仅最后一条用户消息之后的 assistant 轮含 thinking，更早轮次无 thinking。
- Given 开关开启且最新一轮处于工具调用循环中，When 发起请求，Then 循环内 assistant 轮的 thinking（含签名与 redacted_thinking）完整回传，不触发服务商 400。
- Given 开关关闭，When 发起请求，Then anthropic / gemini 请求体不含任何历史 thinking 块（协议强制保留的最新轮除外）。
- Given 会话历史包含 openai 协议时期产生的无签名 thinking，When 切换到 anthropic 模型并发起请求，Then 请求成功（历史 thinking 已被剥离）。
- Given 开关任意状态，When 查看「查看提示词」面板，Then 面板内容与实际发送口径一致（开=含最新轮 thinking）。
- Given 双端任意一端切换开关，When 另一端打开聊天设置，Then 开关状态一致且新请求按新状态生效。

## 风险与待确认项

- 开关默认开但语义从「全历史」变为「仅最新一轮」，对存量长会话是行为变化（上下文占用下降、无智能损失）；发版说明中应提示。
- anthropic 工具循环内「关闭语义」的最低保留集合需在实现时严格对照服务商约束验证，避免 400。
