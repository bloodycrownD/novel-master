# 大文本回滚卡顿修复 PRD（feature ②）

## 背景

mobile 端对大文本消息（单条 content_json 几十~上百 KB）发起回滚后，页面卡顿、界面迟迟不刷新。探索定案（2026-09-23）：回滚执行链在同一时间窗内把 content_json 完整 JSON.parse 至少 3 遍（回滚 plan 全量拉取 → 完成后 tail 41 条 → token 标签全量重算），且快照因「分片阈值 50 条 > tail 页 40 条」恒为单包、片间量子让步完全不生效，webview 侧是无增量的全量 DOM 重建；辅因：回滚事务内含 `deleteGlobalOrphans` 全局全表 DELETE、收尾链（composer 恢复 + token 刷新）同帧叠加。

## 目标

大会话/大消息回滚后界面可感知刷新（真机 <1s 量级），JS 线程不被回滚链长任务串行独占；**回滚语义零变化**。

## 核心需求

1. 回滚链各段耗时可度量（__DEV__ 打点，效果对比有基线）；
2. 全量 parse 的三遍收敛（复用/让步/延后）；
3. 快照分片对大消息生效（字节维度预算）；
4. 全局 revision 孤儿清扫不占回滚事务；
5. 回滚既有行为测试零断言修改通过。

## 验收标准

- AC-1：真机大会话（数百条含大消息）回滚，toast「回滚成功」到界面刷新完成 <1s 量级（录屏）；
- AC-2：回滚相关既有测试全绿（`test/message-checkpoint/*`、chat 回滚链路用例）；
- AC-3：打点显示单段 JS 长任务不超过量子让步阈值量级（无百 ms 级独占段）。
