# 聊天工作区「推送到项目工作区」PRD

## 背景

项目工作区（项目级 VFS，scopeKey `project:{projectId}`）是该项目所有会话的模板母本；聊天工作区（会话级 VFS）在新建会话时自动从母本初始化，此后 agent 的读写都只落在聊天工作区。用户可用「从上级同步」（mobile 聊天工作区工具栏 / desktop 聊天工作区「更多 → 初始化」）随时用母本覆盖聊天工作区。当会话中整理/重写出了满意的内容（设定、大纲、素材），目前没有把它固化回母本的通道，只能手动逐文件复制。用户要求增加反向「推送」按钮，覆盖行为与拉取完全对称。

## 目标（含成功指标）

在双端聊天工作区提供「推送到项目工作区」操作：一键用当前聊天工作区（含 workplace 目录规则）整树覆盖项目工作区。成功指标：推送后，该项目后续新建会话与其它会话「从上级同步」得到的都是推送后的母本。

## 用户与场景

小说作者在某个会话里让 agent 整理或重写了设定/大纲/素材，确认质量后想把成果固化为项目模板，供后续新会话和其它会话使用。

## 范围

### 包含范围

- mobile 聊天工作区工具栏增加推送入口（与现有同步按钮对称）
- desktop 聊天工作区面板「更多」菜单增加推送入口（与「初始化」对称）
- 覆盖语义与拉取完全对称：文件整树覆盖（含删除母本中多余文件）+ workplace 目录规则一并推送
- 推送前确认弹窗，文案明示影响面（覆盖项目工作区 = 该项目所有会话的模板母本）
- 推送后 desktop 项目工作区面板即时刷新

### 不包含范围

- 选择性推送（挑文件/目录）
- 推送历史、撤销或恢复（project scope 无 checkpoint 体系，不做恢复承诺）
- global 域（全局工作区）任何变更
- CLI 推送命令
- desktop 项目工作区面板改名（现标题「会话工作区」与 mobile「项目工作区」不一致；推送相关文案统一用「项目工作区」，面板改名另行处理）

## 核心需求

1. 双端聊天工作区提供「推送到项目工作区」操作，入口与现有「从上级同步」对称放置。
2. 推送为整树覆盖：项目工作区内容被当前聊天工作区完全替换，母本中多余文件被删除。
3. workplace 目录规则与文件纳入规则随推送一并覆盖（与拉取行为一致，用户已拍板）。
4. 推送前必须弹确认，文案讲清「将覆盖项目工作区，影响该项目所有会话的模板母本」。
5. 推送完成后：desktop 项目工作区面板刷新；后续新建会话以推送后母本初始化。

## 验收标准

- Given 项目工作区有文件 A/B、聊天工作区有 B(修改)/C，When 用户在 mobile 点推送并确认，Then 项目工作区内容变为 B(修改)/C（A 被删除）。
- 同一场景在 desktop 聊天工作区菜单操作，结果一致，且不离开当前页即可见项目工作区面板已刷新（面板互斥挂载下即「切换面板后重挂载即见新内容」）。
- Given 聊天工作区中目录规则被修改，When 推送，Then 项目工作区目录规则变为聊天工作区的版本。
- Given 用户点推送，When 未确认弹窗，Then 无任何变更发生。
- 推送完成后新建会话，其聊天工作区初始内容与推送后的项目工作区一致。
- 既有「从上级同步」行为不受影响（回归）。

## 风险与待确认项

- 历史记忆记录过 `replaceVfsSubtree` 存在「删除侧不彻底」缺陷（2026-08-19），实现前须用 CLI template-pull e2e 验证当前已修复（spec 阶段核实）。
- 子会话（subagent session）共享父会话工作区，推送入口只应出现在主会话的聊天工作区——具体判定在 spec 阶段定。
