# 正则系统移除 PRD

## 背景

正则系统是 v1.4.21 上线的消息正文替换功能：「正则组 → 组内规则」两级结构，工作区单指针选定唯一生效组，每条规则可分别配置 llm 通道（发给模型的提示词）与 display 通道（界面展示）的替换文本，按可见消息深度区间与角色过滤，纯视图时替换、不改数据库原文。用户确认整体移除：使用价值不足，历史上还曾引发流式渲染 bug；同时明确接受失去「用户配置正文清洗/脱敏」这一唯一出口（此前「正文清洗由用户正则决定而非框架强制」的决策随之作废）。

## 目标（含成功指标）

正则系统从产品中完全消失：core 数据表与服务、双端 UI、CLI 命令族、消息显示与 LLM 出站链路全部移除，行为回到「原文直出」。成功指标：双端与 CLI 无任何正则入口；升级后存量库中正则数据被幂等清理；聊天显示与 LLM 出站均为原文。

## 用户与场景

全部用户：升级后设置界面更干净。曾配置过正则的用户失去该能力（用户已拍板接受）；其正则数据随升级清理，不做导出。

## 范围

### 包含范围

- mobile：「我的 → 正则配置」入口与全部正则页面（组列表/规则列表/规则编辑）、正则组选择弹窗
- desktop：设置页「正则过滤」三个视图、工作区设置「当前正则组」行与选择弹窗、12 个 `nm:regex/*` IPC 通道
- core：regex 域（`regex_group`/`regex_rule` 两表、domain/service、`@novel-master/core/regex` 导出、KKV 指针）、agent 出站链路的正则应用、消息显示链路的 display 应用
- CLI：`regex`、`regex-group` 命令族及 prompt/message/model 命令中的消费段
- schema：正则表幂等清理（DROP IF EXISTS），schema 版本推进
- CHANGELOG 移除条目

### 不包含范围

- 任何替代性文本清洗/替换机制
- depth 域等共享设施（压缩链路仍在用，保留）
- grep 工具的正则模式、mention 标记检测等功能性 RegExp 使用（与正则系统无关，保留）
- 云端整库快照中历史正则数据的追溯（恢复旧备份后表会被 bootstrap 幂等清理保证不残留）
- examples/mobile 静态原型里的正则页面残留清理（陈年原型，另议）

## 核心需求

1. 双端设置中所有正则相关入口、页面、开关移除，相关 IPC 通道删除。
2. 消息展示与 LLM 提示词出站不再应用任何正则替换，原文直出；提示词预览/token 计数等周边消费点同步回到无正则路径。
3. core 正则数据表随升级幂等清理，schema 版本推进（遵守项目 SCHEMA_BOOT_VERSION 硬规则）。
4. CLI 正则命令族移除，help 中不再出现。
5. CHANGELOG 记录移除条目（该功能 UI 用户实际见过）。

## 验收标准

- Given 升级前库中存在正则组与规则且指针已选组，When 升级启动应用，Then 正则表被清理，应用正常启动无报错。
- Given 任意会话历史消息，When 打开聊天，Then 消息按原文展示（无 display 替换痕迹）。
- Given 升级前配置过 llm 通道替换，When 发送消息触发 LLM 请求，Then 提示词为原文（无 llm 替换）。
- mobile「我的」页与 desktop 设置页均无「正则」入口；CLI 正则命令不存在（help 无此项）。
- core 包不再导出 regex 子路径；全仓测试绿。

## 风险与待确认项

- 移除后用户彻底失去正文清洗配置能力——已拍板接受，记录在案。
- mobile 聊天页系列测试大量 mock 了 display 加载函数（`loadSessionMessages*ForDisplay`），需同步重构，为最大隐性波及面（spec 阶段出逐文件清单）。
