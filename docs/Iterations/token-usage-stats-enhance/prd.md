# 用量统计增强（图表优化 + 速率/首字延迟）PRD

## 背景

`token-usage-stats` 迭代已交付双端用量统计（汇总/明细/分模型），但存在两类问题：

1. **图表体验**：mobile 明细页的堆叠条形图柱组**贴左排布**（柱总宽小于容器时不居中、超宽时横向滚动从左起），视觉失衡；双端图表样式原始——desktop 无图例、无刻度线、悬浮提示用浏览器原生 title、无过渡动画，mobile 虽有图例但同样缺刻度与精细提示。
2. **指标缺口**：统计只有 token 数量与命中率，**没有 token 速率（tokens/s）与首字延迟（TTFT）**。这两项是用户评估「模型快不快、值不值」的核心体感指标，且目前数据侧完全没有采集（消息表无任何耗时字段）。

## 目标（含成功指标）

| 目标 | 成功指标 |
|------|----------|
| 图表对齐修正 | mobile 明细条形图在柱总宽小于容器时**水平居中**，超宽横向滚动行为保留 |
| 图表样式现代化 | 双端图表具备图例、数值刻度/网格、悬浮（或长按）详情提示；与设置页整体视觉风格一致 |
| 新指标可用 | 每次模型请求采集**首字延迟**与**总时长**；汇总与明细可展示平均 token 速率与平均首字延迟 |
| 存量兼容 | 升级用户的历史数据不报错、不出现假值；新指标自本版本起逐步积累，未积累前显示友好空态 |

## 用户与场景

| 用户 | 场景 |
|------|------|
| 日常用户 | 在统计页对比「今天/本周」各时段的用量走势，直观看到每小时消耗 |
| 效能敏感用户 | 对比不同模型的 token 速率与首字延迟，决定创作主力用哪个模型 |
| 排错用户 | 感知「今天回复变慢」时，查看首字延迟趋势是否有异常抬升 |

## 范围
### 包含范围
- mobile 明细条形图居中与样式精修（聊天配置 → 用量统计）
- desktop 统计图表样式精修（图例/刻度/提示/动画）
- 每次模型请求的首字延迟与总时长采集（双端一致口径）
- 汇总与明细新增平均 token 速率、平均首字延迟指标展示
- 存量数据空态文案（沿用「自本版本起开始积累」先例）

### 不包含范围
- 按模型的速率/延迟对比排行（可作后续迭代）
- P50/P95 等分位数统计（本期仅平均值，分位数待数据积累后评估）
- 统计数据导出

## 核心需求（3-7 条）

1. **mobile 条形图居中**：明细页堆叠条形图在可用宽度内水平居中；柱子总宽超出屏幕时保留横向滚动。
2. **图表样式精修**：双端图表补齐图例、刻度与网格、悬浮/长按详情（时间、输入/输出 token 数）；desktop 废弃原生 title 提示。
3. **耗时采集**：每次模型请求记录「请求发起 → 首个内容到达」与「请求发起 → 完成」两个耗时，随用量数据一并持久化。
4. **速率口径**：token 速率 = 输出 token 数 ÷（总时长 − 首字延迟），即排除等待首字的纯生成速率；展示时同时给出首字延迟。
5. **指标展示**：汇总页新增全局平均速率与平均首字延迟；明细页选中日期后展示当日均值；空数据时显示「暂无数据，自本版本起开始积累」。

## 验收标准

- Given mobile 明细页且柱总宽小于屏幕宽度，When 渲染堆叠条形图，Then 柱组水平居中，不贴左。
- Given mobile 明细页且柱总宽超出屏幕宽度，When 渲染，Then 保留横向滚动且可滚动到最右侧柱。
- Given 双端任一图表，When 悬浮（desktop）/长按（mobile）某根柱，Then 显示该时间桶的输入/输出 token 数详情。
- Given 本版本起产生的新模型请求，When 查看汇总页，Then 可见平均 token 速率与平均首字延迟，且速率口径为输出 token ÷（总时长−首字延迟）。
- Given 升级用户且升级后尚无新请求，When 查看新指标区域，Then 显示空态文案而非 0 或报错。
- Given 既有测试断言（柱高顺序、页签行为），When 全量跑统计相关测试，Then 全部通过或随 UI 调整同步更新后通过。

## 风险与待确认项

- mobile「长按详情」与图表区滚动手势可能冲突，实现时需验证交互不互抢。
- 非流式请求的「首字延迟」语义（无流事件时取响应完成时刻）需在实现时明确并在指标上不误导。
