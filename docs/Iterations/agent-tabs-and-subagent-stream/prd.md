# 智能体配置分 Tab 与子会话流式开关 PRD（迭代总纲）

## 背景

智能体体系里「主会话智能体」和「子智能体」共用一套定义与同一个配置列表，双端的智能体配置页目前都是单一列表：主/子混排、不显示作用域、不提供任何过滤。用户管理多个智能体时找不到区分入口；而作用域（`mode`：仅主智能体 / 仅子智能体 / 默认全部）其实早已是定义上的正式字段，运行侧也已有两处既定过滤口径（主会话选择器排除「仅子智能体」；task 工具的可调用名单排除「仅主智能体」），只是列表页没有利用它。

流式方面，主会话早已有「流式输出」开关（默认开，关闭后回复完成后一次性显示），但子会话的流式在核心层是写死的，用户无法关闭。两处流式控制的入口与粒度不一致。

本迭代包含两个 feature，均源自 2026-09-28 的探索与拍板（过程记录见 `docs/apm/memory/20260928-subagent-stream-config-brainstorm.md`）：

- `features/agent-config-tabs/`：智能体配置页拆「主智能体 / 子智能体」双 tab
- `features/subagent-stream-toggle/`：聊天配置新增「子会话流式」开关

## 目标（含成功指标）

1. 双端智能体配置页按作用域分 tab 浏览与管理，与技能管理页的分段 tab 体验一致。成功指标：双端均能按 tab 正确过滤（口径与运行侧两处过滤一致），既有列表操作全部保留。
2. 子会话流式与主会话流式对称可控，统一在聊天配置层管理。成功指标：开关默认开且升级后行为零变化；关闭后子会话消息完整落库、运行状态正常，仅失去实时增量。

## 用户与场景

- 双端（desktop / mobile）使用者；配置了多个智能体、需要区分主/子用途的用户。
- 不需要子会话实时输出、或希望减少流式开销的用户：可一键关闭子会话流式。

## 范围

### 包含范围

- 智能体列表页双 tab 化（双端）、作用域过滤与标记、内置 general 子代理展示、新建默认作用域随 tab。
- 「子会话流式」开关（双端设置页 + 核心偏好存储）及其关闭后的行为定义。

### 不包含范围

- 作用域的运行语义变更（picker / task 过滤 / 工具摘除规则不动）。
- AgentDefinition 数据模型与智能体编辑表单的字段变更（本迭代完全不碰智能体定义结构）。
- desktop 非流式请求的超时策略调整（与主会话开关关闭时的现状保持一致，不新增处理）。

## 核心需求

1. **智能体配置页拆双 tab**：主智能体（默认选中）/ 子智能体，切换即时过滤，形态对齐技能管理页的分段控件。详见 `features/agent-config-tabs/prd.md`。
2. **子会话流式开关**：与「流式输出」并排的独立开关，默认开，关闭后子会话（含递归）走非流式调用。详见 `features/subagent-stream-toggle/prd.md`。

## 验收标准

以两个 feature PRD 的验收清单为准（`features/agent-config-tabs/prd.md`、`features/subagent-stream-toggle/prd.md`），汇总口径：

- 双端行为一致；升级存量用户默认体验零变化（tab 默认在主侧、子会话流式默认开）。
- 既有能力无回归：列表操作（编辑/重命名/复制/删除/批量）与主会话「流式输出」开关行为不变。

## 风险与待确认项

- 关闭子会话流式后，子会话浏览页在生成期间的交互（终止按钮、进行中状态呈现）需实现阶段验证并定义预期（见 feature 2 PRD）。
