# 智能体配置页拆双 Tab PRD

## 背景

双端智能体配置页（mobile「我的 → 智能体配置」；desktop 设置 → 智能体配置）均为单一列表：所有智能体混排，不显示作用域、不过滤。作用域字段（`mode`：`primary` 仅主智能体 / `subagent` 仅子智能体 / `all` 默认全部，未填写按全部解释）已存在于定义中，编辑器里也有「作用域」下拉，但列表层完全没有利用。运行侧已有两处既定过滤口径：

- 主会话选择智能体（picker）时排除「仅子智能体」；
- task 工具挑选可调用子代理时排除「仅主智能体」。

另有一个内置虚拟子代理 `general`（默认子代理，不落库、不可删除、当前不出现在配置列表中），task 实际上始终可以调用它。

用户期望把配置页拆成「主智能体 / 子智能体」两个 tab，形态对齐技能管理页的分段 tab（全局技能 / 项目技能）。

## 目标（含成功指标）

智能体配置页按作用域分 tab 浏览与管理，让主/子用途一目了然。成功指标：双端 tab 过滤口径与运行侧两处过滤完全一致；既有列表操作零丢失；内置 general 子代理在子 tab 可见。

## 用户与场景

- 管理多个智能体的用户：在主 tab 找主会话用的智能体、在子 tab 给 task 调用的智能体做配置，不用再在混排列表里翻。
- 新用户：进子 tab 就能看到内置 general，知道子智能体「开箱即有一个默认可用」。

## 范围

### 包含范围

- 双端智能体列表页的双 tab 化（分段控件、切换过滤、tab 内既有操作）。
- 「默认（全部）/ 未填写」条目的双边显示与标记。
- 内置 general 子代理在子 tab 的展示。
- 新建智能体时默认作用域随当前 tab。

### 不包含范围

- 作用域运行语义（picker / task 过滤 / 仅子智能体摘除 task 与 agent 管理工具）的任何变更。
- 智能体编辑表单的字段变更（作用域下拉保留，不增不减）。
- 会话侧、工作区侧选择智能体入口的改动。

## 核心需求

1. **双 tab 结构**：列表页顶部提供「主智能体 / 子智能体」分段控件，主智能体在前、默认选中；切换即时过滤当前列表，不重新加载全量数据。形态与技能管理页一致。
2. **过滤口径（业务规则，与运行侧对齐）**：
   - 主 tab：显示可作主会话智能体的条目 = 排除「仅子智能体」；
   - 子 tab：显示可被 task 调用的条目 = 排除「仅主智能体」；
   - 「默认（全部）」与未填写作用域的条目：**两个 tab 都显示**，并在条目上带可识别标记（如「全部」徽标），说明其两边可用。
3. **内置 general 子代理**：在子 tab 以内置条目展示（带「内置」标记），不可删除；进入后为**与其他智能体完全相同的完整编辑器界面 + 全部控件禁用态**（2026-09-28 实测反馈拍板：视觉与交互统一，且可查看工具策略、提示词模版等全部配置；顶部保留「内置智能体，不可编辑」说明，保存不可用）。它始终位于子 tab（作用域即「仅子智能体」）。
4. **新建默认作用域随 tab**：在主 tab 发起创建时，新智能体默认作用域为「仅主智能体」；在子 tab 发起时默认「仅子智能体」；默认值随保存落库（不留「未保存即变更作用域」的中间态）。
5. **作用域下拉保留**：编辑器中的作用域下拉仍是修改归属的唯一入口；修改作用域并保存后，条目按新作用域出现在对应 tab。
6. **tab 内操作完整**：编辑、重命名、复制、删除、批量操作在两个 tab 内对各自成员可用；批量选择集按 tab 独立，切换 tab 自动退出批量模式（对齐技能管理页约定）。

## 验收标准

1. 双端打开智能体配置页：默认显示主 tab；分段控件可切换，切换后列表即时按口径过滤。
2. 作用域为「仅主智能体」的条目只出现在主 tab；「仅子智能体」只出现在子 tab；「默认（全部）」与未填写的条目两边都出现且带标记。
3. 过滤口径与运行侧一致抽查：某「仅子智能体」条目不出现在主会话选择器中，也不出现在主 tab；主 tab 成员集合与主会话选择器可选集合一致（排除失效条目的差异后）。
4. 子 tab 显示内置 general 条目并带「内置」标记；对其不提供删除（删除入口不可用或操作被拒绝）；进入后为只读呈现，保存不可用（desktop 保存按钮保留但禁用、mobile 不渲染保存栏）。
5. 在主 tab 新建并保存后，该智能体作用域为「仅主智能体」且出现在主 tab；在子 tab 新建同理为「仅子智能体」。
6. 把某智能体作用域从「全部」改为「仅子智能体」并保存后，它从主 tab 消失、出现在子 tab。
7. 配置失效（数据损坏）的条目在所属 tab 仍可见并保留失效标记（读不到作用域时按「全部」双边显示），不因拆 tab 而丢失。
8. 切换 tab 自动退出批量模式；两个 tab 的批量选择互不影响。
9. 双端行为一致。

## 风险与待确认项

- 「默认（全部）」双边显示会让同一批智能体在两个 tab 重复出现——为与运行语义一致的有意设计（拍板定案），上线后如用户反馈困惑，可再评估行内标记的呈现强度。
