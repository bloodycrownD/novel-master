# 子会话流式开关 PRD

## 背景

主会话已有「流式输出」开关（默认开；关闭后回复完成后一次性显示），存储为三端共享的聊天偏好。子会话（主智能体经 task 工具派生的会话，含其递归派生）则没有对应控制：核心层对子会话的 LLM 调用固定走流式，用户无法关闭。

关闭子会话流式的动机与主会话开关一致：不需要实时输出时省去流式开销/复杂度。底层非流式调用链路（三协议适配）早已完整存在，CLI 亦有非流式先例，本需求是纯增量开关、不涉及新链路。

用户拍板：开关放在聊天配置层，与「流式输出」并排成为「主会话流式 / 子会话流式」两个开关，保持统一；不放进智能体配置。

## 目标（含成功指标）

子会话流式与主会话流式对称可控，统一在聊天配置管理。成功指标：默认开且升级后行为零变化；关闭后子会话消息完整、状态正常、仅失去实时增量；两开关互不影响。

## 用户与场景

- 不需要子会话实时输出（例如长时间后台跑的子任务）、或希望减少流式开销的用户：与主会话一样一键关闭。
- 默认用户：无感，行为与现状一致。

## 范围

### 包含范围

- 双端设置页新增「子会话流式」开关（mobile 聊天配置页、desktop 设置 → 工作区 → 聊天偏好，与「流式输出」并排）。
- 核心层的子会话流式偏好（三端共享存储，默认开）。
- 关闭后子会话（含递归派生）的行为定义。
- CLI 经偏好读写该开关（无 UI，命令行可配）。

### 不包含范围

- 主会话「流式输出」开关的任何行为变更。
- 智能体定义/智能体配置页的任何变更。
- 关闭状态下子会话浏览页的新增信息展示（如「非流式模式」提示文案）——仅保证既有元素不误导。
- desktop 非流式请求的超时策略调整（与主会话开关关闭时的现状一致）。

## 核心需求

1. **开关入口**：mobile 在聊天配置页、desktop 在设置 → 工作区 → 聊天偏好，「子会话流式」开关紧邻「流式输出」，文案说明关闭后果（子会话回复完成后一次性显示）。默认开启。
2. **偏好存储**：作为聊天偏好持久化（三端共享），状态跨重启保留；与主会话流式偏好相互独立。
3. **关闭后的行为定义**：
   - 子会话的 LLM 调用（含子会话内递归派生的孙代理）走非流式；
   - 子会话消息正常完整落库，步骤/回合结束后在子会话浏览页可见（无逐字实时输出）；
   - 运行状态事件（开始/进行/完成/失败）照常发布与展示；
   - 实时增量输出与实时速率指标不再出现（终态用量统计不受影响）。
4. **开启行为不变**：开关开启时子会话行为与现状完全一致（实时输出、实时速率）。
5. **主会话隔离**：本开关只影响子会话；主会话流式仅由「流式输出」控制。

## 验收标准

1. 全新安装与升级后，「子会话流式」默认为开，子会话行为与当前版本一致（实时输出正常）。
2. 关闭开关后发起 task：子会话浏览页无逐字输出；步骤完成后消息整段可见；消息记录完整（含工具往返）；运行状态（进行中/完成）正常展示。
3. 关闭开关后，子会话内的递归派生（子代理再派生）同样无实时输出、结果完整。
4. 关闭「子会话流式」不影响主会话：主会话仍按「流式输出」开关行为（开 = 实时；关 = 一次性显示）。
5. 开关状态修改后重启应用，状态保留。
6. desktop 与 mobile 行为一致；文案均能表达「关闭后子会话回复完成后一次性显示」。
7. CLI 可通过偏好命令查询与修改该开关，修改后对子会话生效。

## 风险与待确认项

- 关闭流式后，子会话生成期间的交互细节（终止按钮是否可用、终止时机、中断后的消息保留）在现有验证中未覆盖，实现阶段需专项验证并将结论固化进 spec 验收。
