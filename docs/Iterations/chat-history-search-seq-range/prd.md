# 聊天记录查询·编号区间筛选 PRD

## 背景

聊天详情页的「聊天记录查询」（desktop 为会话详情抽屉内的查找面板，mobile 为聊天记录搜索页）目前仅支持关键词过滤与向上翻页。消息在会话内以 seq 编号单调排列，mobile 搜索结果卡片已展示 `#编号`，用户对「按编号定位某一段消息」已有心智，但无法按编号范围缩小结果。

长会话（几百楼以上）中逐页翻找或靠关键词猜，效率低；用户经常只想回顾「第 40 到 60 楼之间聊了什么」。

相关业务口径（沿用既有决策）：

- 查询结果**包含被隐藏的消息**（压缩、set-floor 等操作隐藏的消息仍可被查到，mobile 端以降低透明度作视觉区分）——与现有 `chat-history-search` 口径一致，本需求不改变该行为。
- seq 编号在**当前会话现存消息集合**内单调递增；回滚为「删尾」操作，删后剩余编号仍连续；回滚后新消息会从断点复用编号。因此区间筛选定位为**即时查询**能力，不承诺编号跨回滚持久对应同一内容。
- 单条删除消息会留下编号空洞：区间内结果条数可能少于区间跨度，属预期行为。

## 目标（含成功指标）

用户可在两端的聊天记录查询中，按消息编号区间（起始编号 / 截止编号）过滤结果，与关键词筛选可组合使用。

成功指标：

- 在包含 500+ 条消息的会话中，用户通过输入编号区间可将结果缩小到目标段落，无需逐页翻阅。
- 双端（desktop / mobile）均提供该能力，行为与口径一致。

## 用户与场景

- 小说创作者在长篇会话中回看某几楼的世界观设定讨论：知道大致楼层范围（可从 mobile 搜索卡片的 `#编号` 或翻页中获知），直接输入区间定位。
- 用户在回滚 / 压缩过的高层号会话中，想确认「可见范围之外」某段历史内容：依赖「结果含隐藏消息」口径找到被隐藏的消息。

## 范围

### 包含范围

- desktop 会话详情抽屉内查找面板：新增编号区间输入（起始 / 截止，允许只填一端）。
- mobile 聊天记录搜索页：新增编号区间输入（起始 / 截止，允许只填一端）。
- 区间筛选与关键词筛选、向上翻页可同时生效。
- 结果中隐藏消息沿用现有视觉降级处理，不新增特殊标记。

### 不包含范围

- 不改变「查询包含隐藏消息」的既有口径。
- 不引入「跳过隐藏消息的楼层号」概念（该概念仅存在于 CLI 展示层，两套口径历史遗留不一致，本期不统一、不采纳）。
- 不提供按编号跳转定位到聊天流中对应消息的交互（可作后续迭代）。
- CLI 端不新增界面能力（CLI 已有楼层区间相关参数）。

## 核心需求（3-7 条）

1. **区间输入**：两端查询界面提供「起始编号」「截止编号」两个输入项；两者均可留空，留空表示该侧不设限。
2. **区间过滤**：查询结果仅包含编号落在 `[起始, 截止]` 区间内的消息（含边界）；区间无效（起始 > 截止）时给出提示且不返回误导性结果。
3. **组合筛选**：编号区间与关键词可组合（取交集）；与既有向上翻页兼容。
4. **口径一致**：区间内的隐藏消息照常出现在结果中，沿用现有降透明度展示；排序与现有查询一致（按编号倒序）。
5. **双端一致**：desktop 与 mobile 的输入交互、过滤口径、结果表现保持一致。

## 验收标准

| # | Given / When / Then |
|---|---|
| 1 | Given 一个含 100 条消息的会话；When 用户输入区间 40-60 并查询；Then 结果仅包含编号 40 至 60（含边界）的消息，按编号倒序排列。 |
| 2 | Given 同一会话；When 仅填起始编号 80；Then 返回编号 ≥ 80 的所有消息。 |
| 3 | Given 同一会话；When 仅填截止编号 20；Then 返回编号 ≤ 20 的所有消息。 |
| 4 | Given 区间内存在被压缩隐藏的消息；When 按该区间筛选；Then 隐藏消息出现在结果中并带降透明度视觉（与现有关键词搜索行为一致）。 |
| 5 | Given 输入关键词「灵石」且区间 10-50；When 查询；Then 结果同时满足关键词匹配与编号区间。 |
| 6 | Given 起始编号 60、截止编号 40；When 查询；Then 界面给出无效区间提示，不返回结果。 |
| 7 | Given 会话中第 30 条消息曾被单条删除；When 筛选区间 25-35；Then 返回 10 条消息（编号 25-29、31-35），无崩溃或异常提示。 |
| 8 | Given 回滚删尾后又产生新消息的会话；When 按当前列表可见编号输入区间；Then 结果与当前列表内容对应一致。 |

## 风险与待确认项

- 输入交互细节（数值输入框 / 步进器等具体控件形态）由实现阶段按各端惯例确定，PRD 不约束。
- 「按编号跳转定位到聊天流」为潜在后续需求，本期不做，如需要另立迭代。
