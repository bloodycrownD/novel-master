# 数据统计 UI 与时间模型优化 PRD

## 背景

`token-usage-stats-enhance` 交付服务商×模型维度后，日常使用中统计页的浏览动线暴露出几处摩擦：

- 流水列表与时间筛选的关系需要明确与汇总/图表一致：三页签共用一套筛选，避免「改了时间只有部分页签生效」的错位感
- 想"看今天"需要手动配自定义日期；而汇总页的「今日总 token / 调用次数」指标卡与该诉求功能重叠
- 「明细」页签名与「流水」内容存在混淆
- 服务商×模型汇总目前是纯文字列表，用量结构占比不直观
- 时间语义存在历史瑕疵：「近 7 天」实际展示 8 个日桶；时间跨度校验与查询成本耦合，边界口径不自然

## 目标（含成功指标）

> **需求①勘误（2026-09-07，用户拍板）**：原稿「时间筛选不再影响流水列表」为方向记反，实际需求为「时间筛选**继续约束**流水列表」——流水与汇总/图表同窗口，模型/服务商筛选叠加生效；本文档相关目标/范围/验收已按勘误后方向同步修订。

- 流水列表与所选时间窗口一致（含「共 N 条」计数口径），模型 / 服务商筛选叠加生效
- 查看"今天"的数据一键直达，图表直接按小时展开
- 服务商×模型用量结构一眼可读（饼图替换文字列表）
- 时间统计统一为自然日口径（本地 0 点至次日 0 点），近 7/30 天桶数正确

成功指标：三页签同一筛选行为一致，切窗口后流水计数随窗口变化；查看今日按小时数据 ≤1 次点击；饼图与原列表同源数据加载，体感不慢于现状。

## 用户与场景

novel-master 双端（桌面 / Android）用户：查看 token 用量与费用趋势、核对缓存命中表现、翻请求流水定位异常请求的日常场景。

## 范围

### 包含范围

- 双端统计页 UI 调整：流水跟随时间筛选（需求①勘误后方向）、时间筛选新增「今天」、移除今日指标卡、「明细」改名「图表」、「今天」下直出按小时图、饼图替换服务商×模型列表
- 统计时间模型统一为自然日区间；「近 7 天 / 近 30 天」桶数修正为 7 / 30
- 模型 / 服务商筛选与时间筛选叠加作用于流水列表

### 不包含范围

- 统计口径公式变更（命中率、计费分母维持现状）
- 流水页新增每行命中率列或其他新指标
- 桌面端服务商维度筛选增强（维持现有模型筛选）

## 核心需求

1. **流水跟随时间**（需求①勘误后方向）：流水列表受时间筛选约束，与汇总/图表同窗口；模型 / 服务商筛选叠加生效，「共 N 条」按窗口口径计数
2. **新增「今天」时间选项**：一键筛选当日数据；同时移除「今日总 token / 调用次数」指标卡（双端、含空态）
3. **「明细」页签更名「图表」**：与「流水」的命名冲突消除
4. **今天直出按小时图**：时间筛选为「今天」时，图表页跳过按天用量图，直接展示当日 24 小时分布
5. **饼图替换服务商×模型列表**：全部组合正常展示、不折叠——扇区数天然有界（非配置的历史模型按现有口径归并「其他」桶，不随模型更替增长）；点选扇区（或图例）后图下方固定详情行展示该组合的用量、调用次数与占比
6. **自然日口径**：时间统计以本地自然日（0 点至次日 0 点）为单位；「近 7 天」= 今天与前 6 天共 7 个日桶，「近 30 天」同理 30 桶

## 验收标准

- Given 任意时间筛选　When 进入流水页　Then 流水列表按所选时间窗口过滤展示（时间倒序），「共 N 条」按窗口口径计数；模型/服务商筛选叠加生效
- Given 时间筛选 = 今天　When 查看图表页　Then 仅展示当日按小时用量图（24 桶），不出现按天用量图
- Given 时间筛选 = 任意值　When 浏览统计页　Then 页面不再出现「今日总 token / 调用次数」指标卡（含无数据空态）
- Given 服务商×模型饼图　When 点选任一扇区或图例　Then 图下方固定详情行展示该组合的服务商 · 模型、用量、调用次数与占比
- Given 时间筛选 = 近 7 天　When 查看按天用量　Then 恰好 7 个日桶（今天 + 前 6 天）；近 30 天同理 30 桶
- Given 模型筛选选中某模型　Then 流水列表与饼图均只统计该模型
- Given 同一操作在桌面端与移动端执行　Then 行为一致
