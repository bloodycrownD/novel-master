# 项目持久规则

## 术语定义

面向新加入项目的开发者/agent，解释 novel-master 专属名词。定义以 main 当前代码为准。每条附代码索引（主实现文件/目录），路径相对仓库根。

### 消息与提示词层

- **attach（会话附加内容）**：用户发消息时随消息落库的结构化附件（`chat_message.attachments_json`），提示词拼装时 hydrate 成 `<action name="userAttach">` 注入。可附文本文件（带行号全文）、目录（ASCII 树）、图片/二进制（只给文件名不喂正文）。逐消息、消息级。→ `packages/core/src/domain/chat/model/message-attachment.schema.ts`、`packages/core/src/domain/chat/logic/prepare-user-messages-for-prompt.ts`
- **extra info（附加信息 / customAttach）**：agent 配置里的一段自定义文本（`AgentDefinition.prompts.customAttach`），发提示词时经宏展开后以 `<extra-info>` 块注入**最新一条**非 hidden user 消息（历史不注入）。agent 级、同轮共享、只在拼装时不落库。宏展开值取回合快照（见下条）。→ `packages/core/src/domain/chat/logic/wrap-user-message-for-llm.ts`
- **批注（annotate）**：用户在文件预览上划词选中原文并写意见，发送时转成 `source: "user_ops"` + `action: "annotate"` 附件（含 `path`、划词原文、用户意见、定位坐标）。批注草稿存进程内 draft store，不进 composer 草稿。→ `packages/core/src/domain/chat/logic/build-attachment-action-xml.ts`、mobile draft store：`apps/mobile/src/storage/chat-annotate-draft.ts`。**小米/HyperOS 上批注划词菜单不可用（2026-09-28 四轮调查定案，用户拍板 hold 不适配）**：HyperOS 系统级替换 AOSP 文本选区菜单（ActionPopupWindow），react-native-webview `menuItems` 依赖的 `startActionMode` 重写整条不被调用，弹 WebView 默认「复制/搜索/网页分享」；无官方适配口子（dev.mi.com 无文档），小米设备上批注能力接受不可用——**勿当 bug 重复排查、勿立项适配**；标准 Android/Google WebView 实测正常（API37/Chromium153 三重打点证据）。若重启适配：定稿方向「selectionchange + RN 层浮层」（业界绕法，desktop 已有「系统菜单+浮动条」并存先例），打点补丁存 `D:\Dev\nm-worktree\nmAnn-annotate-instrumentation.patch`（MainActivity.kt +7 行，2026-09-30 清理已合并 worktree 时导出；原 nmAnn worktree 与 verify/annotate-menu 分支已删）。完整调查：`docs/apm/memory/20260928-annotate-menu-android-high-version.md`
- **user ops / 操作日志（已拆除）**：曾经的「用户文件操作记录」功能——发送消息时自动把 write/edit/mkdir 等操作以 `source: "user_ops"` 附件附上、UI 渲染成操作 chip。chat-fixes-2026-08 已整体拆除（store/flush 链路、偏好键、设置开关、清推全删）；批注是唯一保留的 user_ops 附件用途。遗留历史消息中的操作日志附件在展示层直接丢弃（过滤非 annotate 的 user_ops，原始数据不删）。新代码不要再读写操作日志链路。→ 拆除：`packages/core/src/service/chat/impl/user-vfs-turn.service.ts`（现状注释）、丢弃口径：`apps/mobile/src/components/chat/message-blocks.ts`
- **hidden 消息**：对 LLM 提示词渲染隐藏的标记——落库保留但不进提示词。只由两种操作产生：压缩和置位。隐藏消息同样支持回滚（回滚不改变可见性）。→ `packages/core/src/domain/chat/model/message.ts`（`hidden` 字段）、过滤逻辑：`packages/core/src/domain/agent/session/`
- **回滚（rollback）**：用户从某条消息发起回滚——截断该消息之后的尾部并恢复正文/批注草稿。对隐藏消息同样可用（无 `!hidden` 前置）；回滚**不改变**任何消息的可见性（`hidden` 标记原样保留，原来是什么样子回滚后还是什么样子）。→ 锚点：`packages/core/src/domain/message-checkpoint/logic/resolve-rollback-anchor.ts`、UI：`apps/mobile/src/screens/tabs/chat-tab/useChatTabMessages.ts`
- **置位（set floor）**：用户显式选一条 user 消息当「地板」，隐藏它之前的全部前缀（锚点必须是 user 消息）。副作用：清空 `rule_snapshot` + `file_cache`，可见历史首次引用状态重置。→ `packages/core/src/service/chat/impl/message-transcript-effects.service.ts`（`setMessageFloorAtMessage`）、`packages/core/src/domain/chat/logic/message-set-floor-range.ts`
- **压缩**：系统按 token 条件自动隐藏最旧一段可见消息。锚定口径（chat-fixes-2026-08 定稿）：`hideStartDepth`（默认 6，尾 depth 0=最新）只是启发式起点——从 slice 最新边界向更旧方向找第一条真用户输入（user 且不含 tool_result），只隐藏**严格更旧**干它的消息，锚点起的整轮（含 tool 往返）保留；压缩后可见历史必以 user 开头，保留条数 ≥ startDepth+1（可以超出启发式值，绝不拦腰切断轮次）。slice 内锚不出真用户输入（病态残留）时放弃本次压缩。副作用：失效 API prompt 占用（进程内热层 + KKV 行双删）；**不清 rule_snapshot/file_cache（2026-09-29 修正：压缩只动消息可见性、与按内容寻址的文件缓存正交，且回合中段清缓存与「前缀回合内冻结」不变量相悖；置位/导入/规则刷新的清除保留）**。→ 执行：`packages/core/src/service/compaction-conditions/run-compaction.ts`、锚定：`packages/core/src/domain/depth/logic/resolve-hide-message-range.ts`。**压缩评估/占用读数走统计优先口径（2026-09-29 用户拍板「像 metric 有哪个用哪个」+ 当晚两次真机复验修正，勿回退）**：agent-runner 每 step 请求完成后回锚 usage（`anchorSeq`=提示词末条消息 seq，本 step 全部落库后写）；读口（`resolve-current-prompt-tokens`）api 命中 = 基线 + 锚点后追加消息的增量估算（`max(heuristic, estimateTokensCjkAware)` 保守下限；附件经 prepare wrap 已入 blocks 天然计入）；**消息纯追加不失效 API 基线**（增量可覆盖——run 起步评估走 api 档零计数），删除/改写/隐藏/置位/导入/切模型类失效保留；本地 miss 完整口径回落**模型自身家族计数器**（glm→原生 DJL、gpt→tiktoken 分块）——**曾试行对 WEB/SP 家族强制 cl100k 估算档，真机复验发现（①assistant 落库与 tool_results 回锚之间的刷新窗口跌估算、首次整串块计数+块表 KKV 读写链引入新卡顿 ②glm 本地档消失），已撤回勿重试**；**评估与 chip 首帧走 `preferEstimate`**（序列化+CJK 感知廉价估算即回，不调驱动）——切模型/回滚后无基线时 run 不为计数阻塞、UI 首帧即显（mobile 后台家族计数经回调升级标签并暖 L1、desktop 后台暖 L1）；估算档（estimated:true）压缩阈值乘 0.85 保守系数。
- **导入缓存对齐（session 导入三件套）**：session scope 的角色卡/ZIP 导入在事务提交后清空该 session 的 `rule_snapshot` + `file_cache` 两域并失效 prompt token cache（与置位/压缩同款副作用），使下次拼提示词时 workplace 前缀按新文件重评估。**口径有意不同**：置位/压缩裸 await（清空失败=状态错乱须报错），导入走 helper 整体 try/catch 吞错 + console.warn（文件已落库，缓存对齐失败不应让导入报错）。门闸是 Core 层 `VfsScope.kind === "session"`（desktop IPC 的 `workspaceScope:"session"` 解析为 project scope，历史命名勿混）；技能 ZIP 安装走 meta-scope 天然不触发；project/global 导入明确不动（拍板）。→ helper：`packages/core/src/service/vfs/logic/clear-session-prompt-caches.ts`、接入：`impl/character-card-import.service.ts` + `impl/vfs-zip-io.service.ts`（工厂内部自建 sessionKkv，对外签名 `(conn, options?)` 不变）、迭代：`docs/Iterations/import-cache-align-and-mermaid-error/`
- **短提示（alreadyReferenced）**：去重机制——同一路径在可见历史第二次进提示词时不再拼全文，只落 `{ path, alreadyReferenced: true }` 短标记。判定按可见序共享 seen 集合（初值是常驻前缀 S0），置位/压缩后重置。→ `packages/core/src/domain/chat/logic/prepare-user-messages-for-prompt.ts`
- **回合快照（macro turn snapshot）**：dynamic 区宏（`$time`/`$week_cn`/`$filetree`）与 customAttach 的展开时机语义——agent run 开始时取一次（时间戳 + 按需预取的 `$filetree`），回合内所有 step 复用同一份文本。目的：回合内每步请求是前一步的纯追加，提升 provider 前缀缓存命中。不丢信息：回合内变更只来自 agent 自己的工具调用，模型已从工具轮次得知；用户侧改动走 `user_vfs_pending` 下回合才生效。不改文本时零预取（沿用 `includes("$filetree")` 预检）。→ `packages/core/src/service/agent/impl/agent-runner.ts`（`resolveTurnFiletreeSnapshot`）、`packages/core/src/domain/prompt/logic/expand-dynamic-macros.ts`
- **seq（消息编号）**：消息在会话内的单调编号，搜索/翻页/回滚都以它为坐标。生成规则 `MAX(seq)+1`；回滚是物理删尾（`DELETE WHERE seq > ?`），删后新消息会**复用旧 seq**（跨时间不唯一，剩余 seq 连续无空洞；中间空洞只来自单条 delete，hide/置位/压缩都是 UPDATE 不删行）。聊天记录查询的「编号区间」（fromSeq/toSeq，闭区间、可单端）沿用搜索口径**含 hidden 消息**（业务拍板）；双端 UI 输入需过滤非数字并归一空串/NaN，repo 层绑定值 `?? null`（better-sqlite3 命名参数不接受 undefined）。→ 生成/回滚：`packages/core/src/domain/chat/repositories/impl/sqlite-message.repository.ts`、区间筛选：同文件 `searchMessages`、查询类型：`packages/core/src/domain/chat/content/message-content-match.ts`
- **composer tag 多行闪烁（已知问题，择期修复）**：mobile 输入框引用 tag（controlled-mentions 内联 span）在多行文本下打字时每键闪烁——最终定性为多行文本变化的全量重排重绘，胶囊内联在 TextInput 内则不可避免（单行不闪、顶到高度上限仍闪，均真机验证）。**两条死路勿重试**：wrapper 层复用 children、patch 库短路冗余重推——均致 tag 消失（children 重推是 span 存续的载体）。候选方案：①编辑中降级纯文本着色、失焦恢复胶囊（triggersConfig 的 textStyle 函数随 focus 切换，约二十行）；②透明输入 + 高亮层 overlay（根治，滚动同步难）。调试日志已于 2026-08-28 摘除；重新排查时可在该文件临时加回（typing/children-push/hydrate 三打点，__DEV__ 门控）。→ `apps/mobile/src/components/chat/ComposerAtPathInput.tsx`、迭代档案：`docs/Iterations/ux-fixes-2026-08/`
- **出站合并（相邻 user 合并）**：anthropic/gemini 的协议适配层在**发送时**把相邻的多条 user 消息合并为一条（anthropic 合并 content、tool_result 块前置；gemini 合并 parts、functionResponse part 前置）——这两家协议不接受连续 user turn（1P API 软合并、Bedrock 拒收），openai 输出 `tool → user` 天然合法零改动。合并不落库，只影响 wire 格式。曾经的 done 桥（tool_turn_bridge，maxSteps 截断后插入的伪造 assistant "【done】" 屏障）已于 v1.5.2 全链路移除，历史会话里的桥消息按普通 assistant 文本出站，存量测试靠内联 `"【done】"` 字面量锁定兼容。→ `packages/core/src/infra/llm-protocol/logic/anthropic-content-mapper.ts`（`mergeAdjacentUserTurns`）、`gemini-content-mapper.ts`（`mergeAdjacentUserContents`）

### 工作区与存储层

- **TDBC 驱动层**：core 与 SQLite 之间的连接协议抽象（`packages/core/src/infra/tdbc/`），实现按平台分包：desktop/cli 用 better-sqlite3，mobile 用 op-sqlite（`packages/tdbc-driver-op-sqlite/`，RN 原生入口走 exports `./native` 子路径）；quick-sqlite 旧驱动（`tdbc-driver-rn`）保留作回滚线——mobile 回滚仅需 `apps/mobile/src/db/connection.ts` 两行（`registerRnDriver` + `driver:'rn'`）加重装 APK。移动端换库根因：Android 12 及以下部分设备临时目录不可写，大事务触发 SQLite 写磁盘临时表报 disk I/O error，靠编译期 `SQLITE_TEMP_STORE=2` 把临时表固定在内存根治。事务内语句一律同步执行（防 async 并发使用同一连接的崩溃），事件循环让步按 16ms 时间量子而非逐语句。→ 协议：`packages/core/src/infra/tdbc/`、驱动包：`packages/tdbc-driver-*/`、移动端接入：`apps/mobile/src/db/connection.ts`
- **常驻工作区（workplace）**：按会话级「规则快照 + 文件缓存」拼装、每轮提示词固定注入在消息前缀的文件树正文（`<workplace>` 块）。归属由 `workplaceScopeSessionId` 定义：主会话指向自身；子会话指向**父会话**（共享父工作区，规则评估按父）。KKV 归属由 `kkvScopeSessionId` 决定（恒等自身——子会话的快照/缓存存自己 KKV，内容从共享 VFS 读）。S0 指常驻前缀的 path 集合，作为短提示判定的初始 seen 集。前缀回合内天然冻结：`loadOrFillFileCache` 命中无条件返回（无 mtime 校验），agent 回合中写盘不会改变前缀；改写缓存的只有用户改规则（`refreshRuleSnapshot`）、压缩/置位、会话删除。另注：`workplace` 工厂每次调用 new 新服务实例，循环内反复获取会使 `liveViewInFlight` 并发去重跨 step 失效——agent-runner 已提升到循环外，新调用方勿再踩。file_cache 存储层已去重化（storage-cache-dedup-and-cleanup）：正文按 sha256(body) 压缩存 `session_file_cache_blob` 全库一份，会话侧 `session_file_cache_entry` 只存 hash+mtime 引用，`SessionKkvService` 六方法语义不变；无引用 blob 由 `runDeferredFileCacheGc`（删除事务提交后调度）回收。→ `packages/core/src/service/workplace/`（装配：`assemble-workplace-display.ts`，服务：`impl/workplace.service.ts`，分流：`domain/session-kkv/repositories/impl/sqlite-session-kkv.repository.ts`）
- **VFS**：项目的虚拟文件系统（逻辑路径树），agent 的 read/write/edit/fs/glob/grep 工具全在它上操作，写入走版本链配合 checkpoint 回滚。scope 分 global/project/session 三层。→ `packages/core/src/domain/vfs/`、工具：`packages/core/src/domain/tool/builtin/`
- **read 引用（contentRef，revision.ref_count 第三类持有者）**：read 工具结果的新消息形态是 `ToolResultBlock.contentRef`（全局键 `entryId+version` 指向源会话 revision + 冗余 `contentHash` 校验、截断派生参数自包含），`content` 置空串；存量全文块（legacy）行为不变、不迁移。ref_count 持有者从两类（checkpoint 指针 + live head）扩为**三类**：read 执行**同步 +1**（先于工具返回，堵「返回→落库」的 sweep 窗口；「输出带 entryId ⟺ +1 已发生」自洽闭环），删除五路径 −1（单删 / 删尾**先于 sweep** / 会话树删 / 项目删 BFS 独立挂点（不经 deleteSessionTree）/ fork·copy 对**源** revision +1）；方向宁多不少（无主 +1 由 `repairRefCounts` 三类期望值检测、只报告不自动修）；pull 不释放（ref_count>0 自动留存）。hydrate 是 view-time：`prepare-user-messages` 接线、内存态填回不写回 content_json，LLM 主链与 token/压缩 parity 链同受益；wire 逐字节等值靠 **`formatReadOutput` 冻结**（演进须版本化）+ 截断管线同参重放。desktop bodyText 引用态显示 `[read ref: path]` 占位。→ 实现：`packages/core/src/domain/vfs/logic/revision-ref-count.ts`、`domain/chat/logic/hydrate-tool-results-for-prompt.ts`、迭代：`docs/Iterations/read-tool-result-ref/`
- **技能域与内置技能**：技能是「SKILL.md + 附属文件」的目录，存在 VFS 独立的 meta 域（global-meta / project-meta scope，与普通文件域隔离），双端支持新建/编辑/启停/ZIP 导入导出。内置技能（首个：`agent-config` 配置指南）由 bootstrap 事务后幂等种入 global 域（用户改过正文则跳过不覆盖）、不可删除；global 域新建/导入同名会撞保留名门（`assertSkillNameNotReservedForCreate`，中文报错，ZIP 导入落盘前同样过门）。编辑已存在技能走 VFS 乐观锁——保存须透传 read 时拿到的 version（`writeSkillFile` 的 `expectedVersion`），否则必撞 CONFLICT。→ 种入：`packages/core/src/bootstrap/skills/seed-builtin-skills.ts`、拦截：`packages/core/src/service/skills/impl/skills.service.ts`

- **移动端（Hermes）没有 WebAssembly：RN 侧只能用纯 JS 压缩实现**（2026-09-28 真机探针实测 `typeof WebAssembly === 'undefined'`，`Atomics`/`SharedArrayBuffer` 同样缺失；RN 0.85.3 的 `ReactAndroid` 里也没有任何 wasm 开关）。因此 `@bokuweb/zstd-wasm`、`brotli-wasm`、`zstd-codec` 这类 **wasm 压缩套件在移动端一律不可用**，能压缩的纯 JS 库只剩 deflate 系（fflate/pako）。业内唯一的纯 TS zstd（`zstdify`）实测**编码器会崩且压不过 deflate**，同样不可用。跨端方案若想让桌面写 zstd/brotli、移动只读，必须先用纯 JS 解码器（如 `fzstd`）验证，别默认移动端解得了。
- **发版 bump 版本号后必须验证 package.json 可解析**：曾有版本行尾逗号丢失导致 JSON 语法错误，`npm ci` 报误导性「lock 不存在」，CI 三平台全挂。提交前跑 `node -e "require('./package.json')"` 逐个验证。另外：bump 用字节级替换只动版本行——desktop `package.json` 是 CRLF 行尾，`json.dump` 重写会全文 diff。发版前须盘点未合并的功能分支清单（v1.5.4 曾漏掉还在 feature 分支上的数据统计，CHANGELOG 缺条目只能强推重打 tag）。
- **改 dist 消费的包必须重建 dist**：Metro/vite 解析的是 exports 指向的 `dist/` 产物（gitignore），src 改完不 `npm run build -w <pkg>`，本地 dev/reload 跑的还是旧代码——v1.4.28 会话复制性能验证曾因 op-sqlite 驱动 dist 停在旧版白测一轮。**合并轮补正（2026-09-29 v1.5.27 实锤）**：跨分支合并后，**凡分支改动过的 workspace 包（含 core 与两个 tokenizer 驱动）都要在 main 上重建 dist 再跑依赖它的 app 测试**——驱动 dist 陈旧会让 desktop 的 T-T9b/T-T9c 在 main 上假红（worktree 里绿、main 上红，且现象像真 bug）；一次 `npm run build -w` 逐个包重建即消。

- **报错在 B 表时先查数据现场**：UNIQUE/约束类报错未必是代码 bug——用 adb run-as 拉真库（或用户 .nmbackup）sqlite3 直查，孤儿行/发号器回退类病灶一眼实锤；干净库复现不了就换真库副本复现。
- **给 @novel-master/core 新增 exports 子路径必须同步 `packages/core/tsconfig.test.json` 的 paths**：paths 缺映射时 tsx 回退 node 解析，经 node_modules 自链加载 `dist/` 旧产物——同一测试进程 src/dist 双份代码并存，测试静默跑旧码且症状诡异（storage-cache-dedup 迭代实锤：listKeys「裸 sid 通、UUID 挂」实为 dist 编译时点造成的假象，排查多轮；修复 5509fb59 补齐 4 条映射）。改 src 后测试行为可疑时，先核对该测试的 import 是否吃到了 dist。
- **VACUUM 与维护类 SQL 直调 conn.execute、不包 transaction**：SQLite 原生拒绝事务内 VACUUM（报错即防护，TdbcConnection 无事务探测 API 不做主动探测）；且事务回调里误用外层 conn 调服务会撞驱动层 AsyncMutex 不可重入（死锁而非报错）——须把回调传入的 tx 喂给服务。维护链路（GC → checkpoint → VACUUM）收敛在 `infra/db-maintenance/`。

- **Android 出包（真机/模拟器 e2e）必须走短路径 junction + 清 `.cxx`**：worktree 深路径会让 autolink 的 CMake 对象路径撞 260 字符上限（`ninja: error: Stat(...): Filename longer than 260 characters`）。配方：`mklink /J D:\nm7 <worktree>` → 删 `apps/mobile/android/app/.cxx` → **从 junction 出包**（`cmd /c "cd /d D:\nm7\apps\mobile\android && gradlew.bat assembleDebug ..."`；注意 msys/PowerShell 的 `cd` 会解析 junction）。**补正（2026-09-29 cuo 实测）：与主仓等长的 worktree（如 `D:\Dev\nm-worktree\cuo`，21 字符根）不要 subst——Node 侧路径解析会把包位置还原成 `D:` 真实根，与 gradle 的 subst 盘工程根混用，`op-sqlite` codegen 的 Java relativize 直接报 `this and base files have different roots`（junction 检查过、autolinking.json 全 subst 路径也无济于事）；这类 worktree 从真实路径直接编即可，主仓能编过它就能编过。subst/junction 只对路径更长的 worktree 才必要。** 另三条同族坑：①autolink 的 Gradle 工程名带 npm scope 前缀（`@novel-master/llm-sse-native` → `:novel-master_llm-sse-native`，写 `:llm-sse-native` 报 project not found，先 `gradlew projects` 查真名）；②内嵌 bundle 配方 = 临时给 `MainApplication.kt` 的 `getDefaultReactHost(...)` 加具名参数 `useDevSupport = false`（RN 0.85，**不是** `useDeveloperSupport`）→ `npm run build:webview:native` → `npx react-native bundle --dev false --entry-file index.js --bundle-output android/app/src/main/assets/index.android.bundle --assets-dest android/app/src/main/res` → **构建后必须 `git checkout` 还原 MainApplication.kt**（`--dev` 必须为 **false**：dev bundle 的初始化代码要求 dev 支持类原生模块如 `SettingsManager`，而 `useDevSupport=false` 恰好不注册它们，组合即启动崩 `Invariant Violation: TurboModuleRegistry.getEnforcing(...): 'SettingsManager' could not be found`——2026-09-28 真机实锤；同日发现生产 bundle 在该真机另崩 `Error: Got unexpected undefined`（minified 栈 `get UIManager`，**未定位、发版前置**），复现用 `--dev false --minify false` 拿可读栈）；③改 `src/web/**` 后必须先 `build:webview(:native)` 再打包，否则 webview 资产是旧的——**新 worktree 首次出包同样要跑 `build:webview:native`，`checkWebViewAssets` 门禁会拦**（2026-09-29 实锤：新建 worktree 无 webview 资产直接 assembleDebug 秒败，报 Missing WebView assets 并给出修复命令）。

- **Windows 出包脚本的两个静默坑（2026-09-28 实锤）**：① **`.ps1` 一律 ASCII-only**——PowerShell 5.1 读脚本按 ANSI 解码，UTF-8 中文注释会变成乱码并**吞掉紧随其后的整行代码**（首次出包就栽在这：`Set-Location` 被吃掉，npm 在仓根跑、报误导性的「Missing script: build:webview:native」；诊断手段是看 npm 的 `_logs/*-debug-0.log` 里的 `cwd`）。② **给 native 命令传带点号的 `-P` 参数必须走 `cmd /c`**：`node scripts/run-gradlew.mjs assembleDebug -PversionName=1.5.25-debase64` 经 PowerShell 转发会被拆坏（gradle 报 `Task '.5.25-debase64' not found`）→ 用 RULE「Android 出包」条目里的 `cmd /c "cd /d <android> && gradlew.bat ..."` 原配方。另：`screencap` 返回**0 字节空图**通常不是 adb 坏了，而是当前有 FLAG_SECURE 窗口（如华为安装确认框）——此时改用 `uiautomator dump` + 解析 XML 拿文字与 bounds（`tmp/dump-ui.mjs` 即此用途）。
- **验收断言的「牙齿」三条判据（2026-09-28 CR 四轮里三轮都在抓同一类缺陷）**：写验收/测试断言时必须自问——① **有牙吗**：把被测实现改成错的（或整段删掉），这条会红吗？恒真的断言是废断言（实例：「第二遍不下发 UPDATE」在「标记短路」与「谓词已空」两条路径下都必然为空）；② **在我的测试文件的进程/顺序/事务约束下可能恒红吗**：进程级模块标记（如 `startupMaintenanceOnce` 的去重 `startupMaintenanceRan`）会被同文件第一条用例消费，导致后续用例里相关路径**永远不可观测**（实例：「标记被清」「同进程二次调用不进入维护段」两条期望永不满足）；③ **同一份夹具只服务一套期望吗**：同一个用例名在两条条目里挂了互斥夹具与期望（实例：「全表皆坏行」既是「纯坏行、零维护」又是「100 坏+20 好、必进维护段」）。**修法**：观测面选与实现同源且可注入的缝（回调计数器优于 SQL 探针），把不可观测的正向路径拆到**独立测试文件**（独立进程）。
- **VFS write/edit/skill 工具的并发语义（无锁，pathTail 同路径串行化为唯一保护层）**：底层乐观锁已按用户 2026-09-06 拍板全拆（60af90b），write 固定 last-write-wins；replace 是「事务外读 → 内存替换 → 写回」非原子。toolRunner.runParallel 的 pathTail 同路径串行化覆盖 **write/edit/fs/skill 四个工具名**（skill 为 2026-09-28 补入——此前 skill 不在名单，同 step 多笔 skill edit 并发互相覆盖「只有最后一条生效」，迭代 `skill-tool-path-serialization` 修复），skill 排队键 `skill:{domain}:{逻辑路径}`（合成单源在 `domain/skills/logic/skill-paths.ts`，与 service 共用；global/project 同名不互串）。两处已知盲区（拍板接受）：pathTail 以原始键比对（vfs 工具同文件不同写法如 `a.md` vs `/a.md` 互不串行）且跨不了 runner 实例（子会话共享父工作区并发同文件仍后写覆盖先写——跨 agent 保护拍板不做）。被覆盖内容可从 revision 历史回滚。编排纪律：同一文件单写者；恢复乐观锁属产品决策勿自行加回。
## 子代理与记忆

- **大规模编队的范围决定权在用户（2026-10-01 用户申斥拍板）**：mega-CR 实锤——主代理以「设计收敛」为由自主把对抗对减半、取消独立双扫波（实际 66 机位 vs 报给用户的编制 150-250），被追责「谁给你的权利自作主张」。纪律：凡向用户报过编制/波次计划，砍波次、减机位、缩覆盖必须**事前请示**；工具替代代理劳动的收敛可自主（质量更优），但**对抗性/验证性覆盖的削减是范围决定，归用户**。承诺的覆盖矩阵要跑满。**计数纪律（同日用户抓包）**：完成数以**磁盘报告对账**为准——完成通知可能多份打包到达、主代理易漏登（实测漏了 13 份）；每次向用户报进度前先 `期望清单 × readdir` 对账，勿凭记忆报数。

- **子代理不得写 `docs/apm/memory/`**：对话记忆由主代理统一维护。曾发生子代理用写文件工具整写覆盖共享记忆文件、丢失既有轮次的事故；记忆的追加/整理/修复只由主代理执行。**2026-09-28 第二次实锤**：code-review-loop 的 spec-fix 子代理越界另建 `20260928-binary-blob-cr-fix-spec-r4.md`（主代理已删除并把内容并入主线记忆）——**派 spec-fix / impl / review 子代理时，prompt 里要显式写「禁止创建或修改 `docs/apm/` 下任何文件」**，只写「只改 fix-spec」不足以拦住它按 AGENTS.md 自作主张补记忆。
- 派发子代理的默认纪律：禁止全仓 grep（内置 search 工具有返回过多内容致上下文爆炸的 bug），定位用 `grep -rln`（只列文件名）+ `sed -n` 定点读；大文件分段读；终端输出截断。
- **子代理派遣模式（2026-09-30 用户改口，覆盖 2026-09-29 同步拍板）**：用户明确「报告落盘、代理只回一行 done，我不看它们的报告，它们对你负责，异步同步都行」。派遣模式由主代理按任务自选：普通迭代可同步（波内同消息并发、阻塞等齐）；大规模编队（数十上百代理）用异步后台批量放、完成即通知随时收割。**两种模式下报告一律落盘、返回信封控制在一行**（`done | 报告路径 | 计数 | top`），防主代理上下文被返回值撑爆——这是硬协议，派单 prompt 里必须显式写。
- **视觉证据必须逐字转写式 prompt + 系统级日志双证**：analyze_image 等视觉模型在「描述式」prompt 下会幻觉出不存在的内容（Step 10 真机验收曾据此虚报「通知 ≤2s 达标」，被用户核对原图识破）。截图取证一律用「逐字转写每张卡片的文字，没有就说没有」式 prompt；关键时序结论另用 logcat / NotificationService / dumpsys 等系统级文本证据交叉验证，不单独采信视觉描述。
- **并行 impl 子代理共享同一 worktree 时禁止 git stash**：曾发生两节点的 stash 互相踩踏（误 pop 对方条目，含历史调试插桩）；验证基线改用临时 worktree 或直接跑测试对照。

- **worktree→主仓（或任何全新环境）首次构建 mobile 的顺序与红线**：①`npm install` 必跑且必须先于 gradle——autolink 按当前 node_modules 扫描，install 前构建的 APK 会缺新原生模块（notifee 事故：运行时 Notifee native module not found）；②`apps/mobile/node_modules` 是 workspace 正常子级安装（未 hoist 到根的包住这里，如 markdown-it），不是垃圾勿整删，但其内容过期会干扰 autolink 依赖识别（识别集合变旧缺新包），过期时清掉重新 npm install；③`local.properties`（sdk.dir）不进 git，新环境要写；④APK 内验证原生模块不能用 unzip -l 按文件名搜（代码编进 classes.dex）——看 PackageList.java 计数或装机运行；⑤模块级 import 的 require-cycle 在依赖解析顺序变化时才暴露运行时错误（worktree 没炸主仓炸），跨环境迁移后启动红屏报 Require cycle 时用使用点惰性 require 打破（import type 保类型）。

- **实时 token 指标语义（用户拍板，2026-09-26，双端一致，勿回退）**：读值 = `max(0, 基线 + 增量估算)`——usage 事件到达时**重锚基线**（`base = 真值 − 当时增量估算`）而不是停止回写；`tokenSource` 只表示基线来源（`usage`/`heuristic`）的 provenance，**不得**再引入「真值后不再回写」的门（该门会让多步 run 的第二步文本冻结、终态无速率，实锤缺陷）。采样器「校正点重 seed」有两类：`source` 翻转 + **窗口折叠后的首个新样本**（相隔 ≥ `SLIDING_TOKEN_RATE_WINDOW_MS`）；**不做「每次 usage 都清窗」**——gemini 每个候选块都 emit usage（`gemini-sse-parser.ts`，累计值变化才发），逐条清窗会把实时速率反复清成 null。实时估算实现为 core `createIncrementalTokenCounter`（尾窗 + 固化，只留尾窗、单次 encode ≤64 字符）＋ 宿主注入的 js-tiktoken 绑定（mobile 用既有依赖 shim；desktop renderer 直接引 js-tiktoken）；未注入估算器时保持 `ceil(chars/3.35)` 旧行为。
