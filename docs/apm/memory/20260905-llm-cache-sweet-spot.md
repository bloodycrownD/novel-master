user:
一般来说长上下文越长，每次消耗就越贵。但实际上因为缓存的原因，减少压缩次数是降低费用的一种方式。也就是说，并不是简单的上下文越长，消耗越多。其实有个甜蜜点。假设 LLM 的上下文为 1M，未缓存是缓存的 10 倍价格，每个消息平均 1000t。帮我算算缓存命中率 99% 和 95% 的甜蜜点分别是多少。

assistant:
先立付费模型：前缀缓存是整段命中或整段脱靶，命中率 h 的真实含义是"平均每 1/(1−h) 轮有一轮整段全价"。每轮期望成本 C(L) = L×p×[0.1+0.9×(1−h)]，括号里是有效单价系数：99% 命中 → 0.109（每轮只付全价 10.9%），95% → 0.145（14.5%）。附带一个好性质：一轮命中省的钱 = 一轮脱靶多付的钱 = 0.9pL，所以一次脱靶只吞掉一轮命中的储蓄，周期净省 89.1%/85.5%，缓存怎么都大赚。

甜蜜点用 1M 窗口锚定：让命中率 h 的长上下文每轮成本追上"满窗口 100% 命中"的理想线（0.1p×1M），解得 L* = 100k÷[0.1+0.9×(1−h)]：
- 99%：100k÷0.109 ≈ 917k ≈ 917 条消息
- 95%：100k÷0.145 ≈ 690k ≈ 690 条消息

含义：骑到这个长度之前，偶发脱靶摊销后的每轮成本仍低于完美缓存的满窗口；过了就性价比倒挂，该压缩。命中率 99→95（脱靶率×5）甜蜜点只缩 ~25%，结构很抗揍。这也是"少压缩=省钱"的量化版：骑到 917k 才压 = ~917 轮付一次压缩后缓存重写的全价账，比在 100k 就压（100 轮一次）少付 9 倍次数。

两个 caveat：① 命中率靠节奏保——GLM 缓存 TTL 实测 3.5~18 分钟，空闲过期一次 917k 全脱就是 10 倍命中轮的账单，节奏慢时甜蜜点大幅前移，早压反而便宜；② 锚定版只用了给定三参数，完整模型还需计入压缩摘要大小与输出价，那只会让最优点再往前挪一点，方向不变。
