# 上下文管理

<ShotStrip :items="[['/screenshots/context.png', '消息菜单：编辑 / 复制 / 置位 / 分叉 / 回滚']]" />

长篇写作时，对话会不断变长，模型的上下文窗口迟早会被占满。上下文管理就是用一组消息级和会话级操作，把真正进入模型的内容收敛到当前需要的范围。本文介绍置位、回滚、压缩、分叉四个核心概念，以及它们各自对应的入口和操作步骤。

## 四个核心概念

| 术语 | 作用 | 对历史消息的影响 |
|---|---|---|
| 置位 | 把某条用户消息定为可见历史的起点 | 它之前的消息不再进入模型上下文，数据保留 |
| 回滚 | 把会话退回到某条消息的状态 | 它之后的消息全部丢弃，不可逆 |
| 压缩 | 隐藏最旧的一段可见消息 | 不再进入模型上下文，数据保留，转录里降透明度显示 |
| 分叉 | 从某条消息起在同一个项目里复制出一个新会话 | 原会话完整保留，新会话自动起名并直接切换过去 |

四个操作可以先记一句话：置位和压缩都是让旧消息不再进入模型，回滚是真的丢掉后面的消息，分叉是另起一条新会话。

### 置位

置位是把某条用户消息定为可见历史的起点。它之前的消息不再进入模型上下文，但这些消息并没有被删除，仍然保存在数据里，随时可以重新置位到别的位置。适合聊完一个阶段、切换话题时使用。

### 回滚

回滚是把会话退回到某条消息的状态，这条消息之后的消息全部丢弃。回滚是真的删除后续消息，不可逆，所以消息菜单里的「回滚」会标红显示，属于危险操作。

### 压缩

压缩是把最旧的一段可见消息隐藏掉。被隐藏的消息不再进入模型上下文，但数据仍然保留，在转录里以降透明度显示。压缩可以由 token 阈值自动触发，也可以在会话详情页手动执行。

### 分叉

分叉是从某条消息起，在同一个项目里复制出一个新会话。新会话会自动起名，原来的会话完整保留；分叉完成后会直接切换到新会话。

### 置位与回滚的区别

这是最容易混的一对操作：

- 置位只改变可见历史的范围。旧消息还在数据里，随时可以再置回别的地方。
- 回滚是真正删掉后面的消息，不可逆。需要留后路时，用置位，不要用回滚。

### 怎么选

- 只想让某条消息之前的旧内容不再进入模型上下文，又不想删数据：用置位。
- 只想缩小上下文占用、保留全部数据：用压缩。
- 想彻底退回到某个节点重来：用回滚，但要注意它不可逆。
- 想保留原会话、从某个节点另起一条线：用分叉。

## 入口速查

| 操作 | 入口 |
|---|---|
| 打开消息菜单 | 对话 tab → 进会话 → 点消息气泡右上角的「⋯」 |
| 进入会话详情页 | 对话 tab → 顶栏 ☰（对话态） |
| 手动压缩上下文 | 对话 tab → 顶栏 ☰（对话态）→ 会话详情页 → 压缩上下文 |
| 配置自动压缩 | 我的 → 聊天配置 |
| 查看实际发送的提示词 | 对话 tab → 顶栏 ☰（对话态）→ 会话详情页 → 查看提示词 |

## 操作前检查

- 消息菜单只在具体会话里可用：先进入对话 tab 的对话态，再点消息气泡右上角的「⋯」。
- 手动压缩的入口在会话详情页，不在会话列表里。
- 压缩、置位、分叉都要求 Agent 不在运行；遇到拒绝提示时，等这一轮运行结束再操作。
- 自动压缩的配置入口是「我的 → 聊天配置」，和手动压缩的入口不是同一个地方。

## 消息操作菜单

**入口：对话 tab → 进会话 → 点消息气泡右上角的「⋯」**

在对话 tab 里进入任意会话，点消息气泡右上角的「⋯」即可打开消息菜单。菜单会按消息类型显示不同的项。

| 菜单项 | 出现在 | 干什么 |
|---|---|---|
| 编辑 | 有正文的消息 | 改内容重新发出去，内容不能为空 |
| 复制 | 所有消息 | 复制正文 |
| 置位 | 只有用户消息，且不是在工具卡里点的 | 把这条定为可见起点 |
| 分叉 | 所有消息 | 从这条起在同一项目里复制出一个新会话，并直接切过去 |
| 回滚 | 所有消息（标红，危险操作） | 退回这条，丢弃后面的 |

### 编辑

「编辑」只对有正文的消息出现。编辑会改掉消息内容并重新发出去，内容不能为空，留空保存不了。

### 复制

「复制」对所有消息出现，作用是把消息正文复制出来。

### 置位

「置位」只对用户消息出现，而且不能是在工具卡里点开的菜单。选中后，这条消息成为可见历史的起点。

### 分叉

「分叉」对所有消息出现。执行后从这条消息起，在同一个项目里复制出一个新会话；新会话自动起名，原来那条线完整保留，并直接切换过去。

### 回滚

「回滚」对所有消息出现，菜单里标红，是危险操作。执行后会话退回这条消息，后面的消息全部丢弃，不可逆。

::: tip
菜单里没有「置位」，通常是因为这条不是用户消息，或者菜单是从工具卡里点开的。
:::

::: warning
「回滚」会丢弃目标消息之后的全部消息，且不可逆。需要保留后路时，优先使用「置位」。
:::

## 手动压缩上下文

**入口：对话 tab → 顶栏 ☰（对话态）→ 会话详情页 → 压缩上下文**

先进入对话态（已经打开某个会话的聊天界面），再点顶栏的 ☰ 进入会话详情页。只有在对话态点 ☰ 才会进入会话详情页；在列表态点 ☰ 打开的是项目抽屉。

会话详情页从上到下依次是：

1. 大字标题，点一下可以直接就地改名。
2. 「当前智能体」卡。
3. 「当前大模型」卡。
4. 「查看提示词」卡。
5. 「压缩上下文」卡，副标题是「减少上下文占用」。
6. 「技能」卡，副标题是「查看与管理」。

### 操作步骤

1. 在对话 tab 里进入要处理的会话。
2. 点顶栏的 ☰，进入会话详情页。
3. 点「压缩上下文」。
4. 在确认框「将压缩上下文。是否继续？」里点「压缩」。
5. 压缩完成后会提示「已压缩」，被隐藏的旧消息在转录里显示为降透明度。

::: warning
如果 Agent 正在运行，压缩会被拒绝，提示「请稍候 / Agent 运行中无法压缩」。等这一轮运行结束后再压缩。
:::

## 自动压缩配置

**入口：我的 → 聊天配置**

在「聊天配置」页的「压缩配置」区可以配置自动压缩。这一段有三个设置。

### 「隐藏起始深度」

数字输入，默认值 6。从这个深度开始折叠，也就是保留最近多少层内容。这个设置对自动压缩和手动压缩都生效。

### 「启用自动压缩」

开关，默认关闭。打开后，满足 token 比例阈值时会自动压缩。

### 「Token 比例」

数字输入，默认 0.8。只有打开「启用自动压缩」之后才会出现。含义是上下文占用超过模型上限的这个比例时触发压缩。

### 保存方式

「压缩配置」这一段没有保存按钮，保存是即时的：开关一切换就落库，数字输入框编辑完、收起键盘就落库。

### 校验与失败处理

填写有误时会拦下，并提示：

- 「Token 比例需为数字」
- 「隐藏起始深度需为数字」
- 「启用时至少填写 token 比例」

写库失败时，开关会自动弹回原值，并提示「保存失败」，不会留下一个假状态。

### 配置建议

- 刚开始写、模型上下文较大时，可以先不开自动压缩，靠手动压缩更可控。
- 长时间挂着写、经常忘记压缩时，可以打开自动压缩，把「Token 比例」设为 0.7～0.8，「隐藏起始深度」保持默认 6。
- 压得太狠会丢细节，压得太松容易顶到模型上限。

手动压缩在会话详情页执行，自动压缩在满足阈值时触发；两者共用「隐藏起始深度」，被隐藏的消息都保留数据。

::: tip
「Token 比例」只有在「启用自动压缩」打开后才会出现。开关没打开时没有这一栏，也就没有阈值，自动压缩不会触发。
:::

## 会话详情页

**入口：对话 tab → 顶栏 ☰（对话态）→ 会话详情页**

会话详情页除了手动压缩，还承载会话级的其他操作：

- 点大字标题，可以直接修改会话名。
- 点「当前智能体」卡，可以更换当前智能体。
- 点「当前大模型」卡，可以更换当前模型。
- 点「查看提示词」卡，进入提示词预览页。
- 点「技能」卡，进入技能面板。

### 智能体被删除时

当会话绑定的智能体被删除时，「当前智能体」卡会解除锁定，卡上提示「智能体已删除 · 点击重选」。重新选择一个智能体即可恢复。在重选之前，「当前大模型」卡一直保持锁定，因为智能体已经不存在，它固定的模型也无从解析。

::: tip
会话列表里没有这个页面的入口。必须先进入对话态，再点顶栏的 ☰；在列表态点 ☰ 打开的是项目抽屉。
:::

## 查看提示词

**入口：对话 tab → 顶栏 ☰（对话态）→ 会话详情页 → 查看提示词**

上下文出现问题时，最应该先看的就是实际发送给模型的内容。

页面按三层结构组织：

1. 轮摘要卡，可以就地展开收起。
2. 区块卡流。
3. 点叶子卡进入「轮详情」，把某一段提示词或某条工具结果整段铺开，可以长按复制。

页面为空时显示「（空提示词）」。

工具结果卡（`search`、`curl`、`grep` 之类）点开后，也进入同一个「轮详情」页。

## 常见问题

### 长按消息气泡没有出现菜单

长按打开菜单的方式已经移除，现在只有消息气泡右上角的「⋯」。

### 在会话列表里找不到压缩入口

会话列表里没有这个入口。需要先进入对话态，再点顶栏 ☰ 进入会话详情页，从「压缩上下文」卡执行。

### 压缩时提示 Agent 正在运行

压缩会被拒绝，提示「请稍候 / Agent 运行中无法压缩」。等这一轮运行结束后再操作。

### 置位或分叉时被拒绝

Agent 正在运行时，置位和分叉同样会被拒绝，分别提示「Agent 运行中无法置位」「Agent 运行中无法分叉」。等这一轮运行结束再操作。

### 以为置位会删掉旧消息

置位不会删除数据，只是把某条用户消息定为可见历史的起点，它之前的消息不再进入模型上下文，之后仍然可以重新置位。回滚才会丢弃后续消息，而且不可逆。

### 编辑消息后保存不了

编辑消息的内容不能为空，留空无法保存。

### 打开自动压缩后没有反应

先确认「启用自动压缩」是否已经打开。「Token 比例」只有在开关打开后才会出现；开关没有打开时就没有阈值，自动压缩不会触发。
