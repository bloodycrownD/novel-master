﻿## 背景
继 vfs-move-and-frontmatter-bugfix 之后，用户实测反馈：键盘抬升与 FM 双重渲染已修复通过；但目录重命名仍有残留（A 改名 B 后 A、B 都在），并伴随"删除文件夹后 UI 仍显示、点击报 NOT_FOUND"的新症状。两者同源：mobile workplace 规则层未清理旧前缀。

## 目的
修掉重命名残留与删除残留两个 bug，让 VFS 文件管理器在重命名 / 删除后 reload 不再出现幽灵目录。

## 现状
根因定位与修复完成（feature/test-batch）：
- 重命名：apps/mobile/src/services/workplace-operations.service.ts 的 migrateWorkplaceDirRename 此前只 copy 规则到新路径、注释说"等 Core 暴露 delete"，实际 Core 早有 deleteRulesUnderLogicalPrefix。已追加 workplace.deleteRulesUnderLogicalPrefix(oldDir)。
- 删除：vfs-operations.service.ts 的 deleteScopedVfsEntry 原本是 VFS 删除在前、workplace 清理在后；若删的是幽灵目录，VFS 抛 NOT_FOUND 导致 workplace 清理不执行。已改为 try/finally 保证 cleanup 总执行。
- 补回归测试 apps/mobile/__tests__/workplace-operations.test.ts（mock stub 验证迁规则后调 deleteRulesUnderLogicalPrefix），通过；vfs-move-path / workplace-block 旧测试未破坏。待用户真机验收。
