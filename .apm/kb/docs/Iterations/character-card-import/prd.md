# 导入角色卡 PRD

## 背景

写作用户常从酒馆（SillyTavern）导出角色卡（PNG 内嵌元数据，或纯 JSON），希望把其中的设定文本迁入 Novel Master 工作区，当作普通 Markdown 文件使用。

本产品已有目录级「导入 ZIP」：确认后**覆盖当前（或指定）文件夹子树**，同级路径保留；**不管** workplace 规则表。用户明确要求：导入角色卡与导入 ZIP **同一目的、同一覆盖语义、同一规则处理方式**——角色卡只是另一种「内容打包格式」，拆完仍是往当前文件夹写入文本文件，而不是移植酒馆的世界书扫描、启用态、深度等运行时规则。

现状：工作区可导入 ZIP /（Desktop）批量文本文件；**没有**角色卡专用入口；PNG 若当普通文件导入会被当作非 UTF-8 跳过，无法得到 md 树。

## 目标（含成功指标）

| 目标 | 成功指标 |
|------|----------|
| 迁入设定文本 | 用户可用 PNG 或纯 JSON 角色卡，在目标文件夹得到约定好的 md 文件树（角色描述 / 开场 / 世界书） |
| 与 ZIP 同语义 | 确认导入后，**仅目标目录子树**被替换为本次生成文件；同级路径全部保留；取消或不确认则子树不变 |
| 规则从简 | 导入**不**读写 workplace 规则表（与 ZIP 一致）；不实现关键字扫描、启用态、depth 等酒馆逻辑 |
| 三端可达 | Desktop、Mobile、CLI 均可完成一次成功导入（入口形态对齐各端既有「导入 ZIP」习惯） |
| 可预期落盘 | 字段→路径映射、世界书命名与重名处理、世界书 Front Matter 键名符合下文约定，可用样卡验收 |

## 用户与场景

| 用户 | 场景 |
|------|------|
| 章节 / 人设作者 | 在工作区某文件夹（可新建后进入）导入角色卡，用生成的 md 做人设与开场素材 |
| Desktop 用户 | 在目录行或空白区（≡ 根）右键，选择「导入角色卡」，选 PNG 或 JSON |
| Mobile 用户 | 进入目标文件夹 → 更多 →「导入角色卡」，用系统文件选择器选 PNG 或 JSON |
| CLI / 脚本用户 | 对指定 scope 与路径执行角色卡导入（须显式确认开关，对齐 `import-zip --yes` 习惯） |

## 范围

### 包含范围

1. **输入格式**：SillyTavern 角色卡 **PNG**（内嵌 `chara` 元数据）与 **纯 JSON** 角色卡。  
2. **写入语义**：与目录级 ZIP 导入一致——确认后**清空并替换目标目录子树**，同级不受影响；失败或不确认则目标子树不变。  
3. **字段提取与落盘**（只要文本，不移植酒馆规则）：  
   - `description` → `角色描述.md`（正文为描述全文）  
   - `first_mes` + `alternate_greetings` **合并**为开场列表 → `开场/开场001.md`、`开场/开场002.md`…（三位数字对齐；不区分主/备选；有内容才编号落盘）  
   - `character_book.entries` → `世界书/<条目名>.md`（见命名规则）；**不论**条目 `enabled` 与否均导入正文  
4. **世界书条目命名**：优先 `comment`（备注/标题）→ 空则用第一个 `key` → 再空则 `条目N`；路径非法字符须清洗；**同目录内文件名必须唯一**，冲突时加后缀（如 `原神.md`、`原神-2.md`），不得因重名互相覆盖丢条目。  
5. **世界书 Front Matter**：写入 `keywords:`（数组/列表，来自条目 keys）；**不**据此做运行时扫描。可同时保留便于人读的其它非规则元数据（若有），但产品不承诺酒馆语义。  
6. **入口**：Desktop / Mobile / CLI；挂载位置与确认心智对齐「导入 ZIP」（并列菜单项或等价命令），确认文案须说明将覆盖目标目录下全部文件、同级不受影响。  
7. **作用域**：与 ZIP 相同，可用于当前工作区所在域（global 模板 / project 模板 / session 工作区）下用户指定的目标目录。

### 不包含范围

- 酒馆世界书关键字扫描、constant、depth、probability、selective、递归等运行时逻辑  
- 按启用态过滤或同步 workplace「展示/隐藏/跟随」规则  
- 导入时清理或重建 workplace 目录/文件规则表（与 ZIP 一致；若需规则同步另开需求）  
- 将开场自动写入聊天首条消息 / 会话历史  
- 角色卡内图片资源、加密卡、非角色卡用途的任意 PNG  
- 把 `personality` / `scenario` / `system_prompt` / `creator_notes` 等未点名字段纳入本期必导集合（本期只保证上述三组落盘）  
- Desktop 拖入 PNG 当「批量文本导入」的顺带解析（本期以显式「导入角色卡」入口为准）

## 核心需求

1. **角色卡 = 另一种导入源**：用户目标是「往当前文件夹导入一批文本文件」，覆盖语义、确认、失败不污染，与「导入 ZIP」对齐。  
2. **只落文本文件树**：生成物为 UTF-8 Markdown；不把 PNG/JSON 原文件当作工作区正文保存（除非产品另有备份需求，本期不要求）。  
3. **开场合并编号**：`first_mes` 与 `alternate_greetings` 按稳定顺序合成列表后，从 `开场001` 起连续编号（三位数字对齐，如 `开场010`）；二者对用户无主备区别。  
4. **世界书只要正文 + 关键字头信息**：正文为条目 content；`keywords` 进 Front Matter，供人读与「头信息」档展示；明确**不会**像酒馆一样按关键字自动插入。  
5. **忽略启用态**：`enabled: false` 的条目仍生成文件——Novel Master 与酒馆是两套系统，不承接其开关语义。  
6. **三端能力等价**：同一张合法卡、同一目标相对路径，在 Desktop / Mobile / CLI 导入后，目标子树内路径集合与关键正文一致（允许换行符等平台无关差异按项目既有文本约定处理）。  
7. **解析失败可理解**：无法识别为角色卡、缺关键结构、或无法解码元数据时，给出明确失败反馈，且**不**清空目标子树。

## 验收标准

- [ ] Given 目标目录 `/角色` 下已有无关文件，且同级有 `/大纲`，When 用户确认导入合法 PNG 角色卡到 `/角色`，Then `/角色` 下仅剩本次生成的 md 树（含 `角色描述.md`，以及卡内开场/世界书对应文件），且 `/大纲` 不变  
- [ ] Given 同上，When 用户取消确认或未确认，Then `/角色` 字节级不变  
- [ ] Given 合法纯 JSON 角色卡，When 在 Desktop / Mobile / CLI 分别导入到等价目标路径，Then 三端子树内相对路径集合一致，且 `角色描述.md` 正文等于卡内 `description`  
- [ ] Given 卡内同时有非空 `first_mes` 与 N 条 `alternate_greetings`，When 导入成功，Then `开场/` 下存在连续的 `开场001.md`…`开场{三位对齐的 N+1}.md`，内容分别为合并列表中的各条开场全文  
- [ ] Given 世界书两条条目 `comment` 均为「原神」（或清洗后同名），When 导入成功，Then 生成互不覆盖的两个文件（如 `原神.md` 与 `原神-2.md`），正文分别对应两条 content  
- [ ] Given 世界书条目含 keys `["原神","原批"]`，When 打开对应 md，Then Front Matter 含 `keywords` 列表且包含上述关键字；正文为 content  
- [ ] Given 某条目 `enabled: false`，When 导入成功，Then 该条目仍有对应 md 文件  
- [ ] Given 非法 PNG/非角色卡 JSON/损坏元数据，When 尝试导入并（若有）确认，Then 导入失败提示可见，且目标子树不变  
- [ ] Given 导入完成，When 检查 workplace 规则表，Then 未因本次导入而被清理或按酒馆规则重写（与 ZIP 行为一致）  
- [ ] Desktop / Mobile 存在与「导入 ZIP」并列可发现的「导入角色卡」入口；CLI 存在可文档化的等价命令（含确认开关）

## 风险与待确认项

| 项 | 说明 |
|----|------|
| 卡片规格版本 | 本期以常见 **Character Card V2**（`spec: chara_card_v2`）及与之字段兼容的 JSON 为主；V1 / V3 / CharX 若结构不同，SPEC 需写清支持边界与失败行为 |
| 空字段 | **已定案（见 SPEC）**：`角色描述.md` 始终生成（正文可为空）；开场合并列表为空则不建 `开场/`；无有效世界书条目则不建 `世界书/` |
| 确认文案 | Desktop / Mobile 均复用 ZIP 覆盖语义句，仅标题改为「导入角色卡」；是否在文案中提示「不会修改目录规则」可选，默认可不提以保持与 ZIP 一致 |
| 与 Mobile「迁入只走 ZIP」口径 | 本需求显式新增「导入角色卡」入口，与 ZIP 并列，不恢复已撤的「任意单文件导入」 |
| 成功 Toast 用词 | 建议统一为「已导入角色卡」类句式；三端措辞可在实现时微调，验收以「用户能感知成功」为准 |
