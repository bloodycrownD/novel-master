# mobile-vfs-longpress-multiselect-move Feature PRD

## 背景与变更动机

Mobile 工作区文件管理器（`VfsFileManager`）同时提供单文件导入/导出与 ZIP 导入/导出，菜单项偏多；「批量操作」需从 ⋯ 菜单进入，且多选栏带「开启/关闭」目录规则，与「整理文件」心智混杂。用户希望：**内容迁入迁出只走 ZIP**；多选改为**长按进入**；多选栏聚焦删除与**同工作区内移动**。

## 范围说明（相对原需求）

相对父级 `import-export-navigation-fix`（DB 备份隔离、工作区返回手势、ZIP 乱码/覆盖）本敏捷为 **Mobile VFS 交互增强**，不改 ZIP 编解码与 DB 备份语义。

### 包含

1. 移除单文件导入/导出入口与实现接线（Mobile）；保留 ZIP 导入/导出。
2. 移除「批量操作」菜单入口；长按文件/文件夹进入多选并勾选该项。
3. 多选栏移除「开启/关闭」；增加「移动」。
4. 文件菜单移除「打开」「导出」；目录菜单保留「导出 ZIP」。
5. 批量移动仅在**当前打开的 VfsScope** 内（不跨项目、不跨会话）；目标目录用复用自 `@` 引用选择器的单选目录模式。

### 不包含

- Desktop / CLI 交互变更
- Core `createVfsBatchIoService` 删除
- 跨 scope 移动、剪切板式跨会话粘贴
- 批量目录规则开关（仍可在单行「状态变更」中处理）

## 影响模块与接口

| 模块 | 影响 |
|------|------|
| `apps/mobile` `VfsFileManager` | 菜单、长按、批量移动编排 |
| `VfsBatchHeader` | 操作按钮集合 |
| `FileReferencePicker` | 新增 `pick-directory` 模式；默认 `at-ref` 不变 |
| `vfs-batch.service.ts` | Mobile 侧删除（仅服务单文件 IO） |
| Core `moveVfsPath` | 复用，不改公开 API |

## 验收标准

1. ⋯ 菜单无「文件导入」「批量操作」；有「导入 ZIP」。
2. 文件 ⋮ 无「打开」「导出」；目录 ⋮ 仍有「导出 ZIP」。
3. 长按任一行进入多选并勾选该行；多选栏仅「取消 / 删除 / 移动」（及已选计数）。
4. 「移动」弹出目录选择器，确认后将选中项移入目标目录；不可移入自身或子目录；目标已存在同名则跳过并提示，其余继续。
5. 全局 / 项目 / 会话工作区各自只能在本 scope 内移动。
6. ChatComposer `@` 引用选择器行为与改前一致。

## 测试用例

| ID | 步骤 | 期望 |
|----|------|------|
| T1 | 打开工作区 ⋯ | 无文件导入/批量操作；有导入 ZIP |
| T2 | 长按文件 → 移动 → 选其它目录 | 文件出现在目标目录，源路径消失 |
| T3 | 选中目录 A，目标选 A 或其子目录 | 提示不可移动，未破坏树 |
| T4 | 目标下已有同名 | toast 跳过，其它项仍移动 |
| T5 | Chat 打开 `@` 引用 | 仍可多选文件/目录插入 token |
