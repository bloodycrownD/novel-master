# 服务商身份与展示名（provider-identity）PRD

> **类型**：配置域身份改造 / 体验对齐  
> **平台（验收）**：Mobile + Desktop + CLI  
> **关系**：修订 `provider-model` 的服务商身份合同；修订 `saved-model-identity` 的模型主文案前缀合同；**正式撤销** `mobile-bugfix` 中「移除服务商展示名称、改以服务商 ID 展示」的决策。

## 背景

当前服务商（Provider）以用户自选或内置的可读字符串 **`providerId`** 同时充当技术主键、命令句柄与（在 Mobile 上）主展示。可选字段 `displayName` 在 Desktop 部分用于列表/重命名，在 Mobile 经 `mobile-bugfix` 被刻意从编辑与展示中移除，三端体验不一致。

已保存模型侧已完成「内部 UUID 指针 + 用户可编辑 `modelName` + 派生主文案」分离（见 `saved-model-identity`），但主文案公式仍为 `{providerId}/{modelName}`，前缀继续暴露服务商技术 id。

产品诉求：

- **对人**：服务商相关流程只出现可读的「服务商名称」，不出现技术主键；
- **对内**：服务商技术主键改为 **UUID**（含存量升级）；
- **对 CLI**：按新合同改写，**不考虑**对旧 `--providerId` slug / 旧 list 习惯的兼容；
- **模型主文案**：前缀改为服务商名称，避免 UUID 或旧 slug 进入默认展示。

本迭代不解决「是否为性能而换主键」类基础设施议题；动机是身份与展示分离、三端体验一致。

## 目标（含成功指标）

| 目标 | 成功指标 |
|------|----------|
| 名称优先 | Mobile / Desktop 服务商列表、详情标题、创建/编辑身份字段、Agent 选服务商等主路径，默认文案均为非空「服务商名称」 |
| 技术主键隐藏 | 上述 UI 主路径不展示服务商 UUID；创建表单不要求用户填写技术主键 |
| 名称必填 | 创建与编辑均不可提交空/纯空白名称；存量升级后每条服务商均有非空名称 |
| 主键 UUID 化 | 升级后库内服务商技术主键均为 UUID；引用方随升级一致可用（对话、已保存模型归属、密钥仍指向正确服务商） |
| 模型主文案可读 | 默认模型展示为 `{服务商名称}/{modelName}`，主文案中不出现服务商 UUID |
| CLI 新合同 | `nm provider` 创建/列表/当前/选用等按「名称对人、UUID 可给脚本」工作；旧「用户自选 slug 作 `--providerId`」不再作为支持路径 |
| 三端一致 | Mobile、Desktop、CLI 对「名称必填、主路径不见技术主键」的产品语义一致 |

## 用户与场景

| 用户 | 场景 |
|------|------|
| Mobile / Desktop 配置用户 | 添加服务商时填写「服务商名称」及连接信息（协议、Base URL、API Key 等），不填写技术 id |
| 同上 | 在列表/详情/Agent 下拉中只通过名称辨认服务商；可改名，改名后各处展示与模型主文案前缀同步为新名称 |
| 聊天 / 选模型用户 | 模型选择器、当前模型、Agent 模型提示等默认看到「服务商名称/模型名」，而非 UUID 或旧 slug |
| CLI 用户 / 脚本 | 按新命令合同创建（必填名称）、列出（含名称；可含 UUID 供脚本）、编辑/删除/use；不依赖旧可读 `--providerId openai` 脚本继续可用 |

## 范围

### 包含范围

1. **服务商身份**
   - 技术主键为 UUID；用户创建时由系统生成，用户不填写。
   - 用户可见、可编辑的身份字段为「服务商名称」（对应现有业务上的展示名概念）；**必填**，禁止空或纯空白。
   - 存量数据升级：原可读 id / 空展示名等，须保证升级后每条均有非空名称，且引用（已保存模型归属、密钥、当前服务商指针等）仍正确。

2. **UI（Mobile + Desktop）**
   - 列表、详情标题、导航、Agent 选服务商、创建/编辑中与「叫什么」相关的主文案：一律服务商名称。
   - 创建/编辑表单：去掉「Provider ID / 服务商 ID」类用户输入；保留协议、Base URL、API Key、Headers 等连接与协议字段（本需求「只出现名称」指**身份字段**，不是整页只留一个输入框）。
   - 撤销 Mobile「只展示 id、不编辑展示名」的既有产品行为。

3. **模型默认主文案**
   - 将 `{providerId}/{modelName}` 的用户主展示改为 `{服务商名称}/{modelName}`（重名等歧义时可用次要信息区分，但默认主行不以服务商 UUID 为前缀）。

4. **CLI**
   - 按新身份模型提供创建（必填名称、系统生成 UUID）、列表/当前/选用/编辑/删除等能力；创建与编辑改名统一用名称旗标（如 `--name`）。
   - **不**承诺旧 slug `--providerId`、旧文档示例与旧脚本兼容。
   - **不**承诺旧 env 名兼容：密钥 env `NOVEL_MASTER_PROVIDER_<…>_API_KEY` 随服务商 UUID ref 变化；旧如 `NOVEL_MASTER_PROVIDER_OPENAI_API_KEY` 本迭代**不再**作为支持路径（与「CLI 不考虑兼容」一致，不做按 `builtin_key` 回落旧名）。

5. **内置服务商**
   - 对用户同样只展示名称（如既有「OpenAI」等友好名）；技术主键是否为 UUID 对用户不可见。
   - 内置不可删、协议不可改等产品护栏保持。

### 不包含范围

- 仅为数据库性能 / 索引策略而引入有序 UUID、雪花算法等（非本需求动机）。
- 跨设备云同步服务商表策略变更（若现网本就不同步服务商，维持现状）。
- 已保存模型的「多预设 / modelName / 模型 UUID 指针」能力本身（已由 `saved-model-identity` 交付）；本迭代只改**展示前缀所依赖的服务商名**。
- iOS 专项验收（若与 Android 同源可顺带，但不作为本 PRD 强制项）。
- 恢复或长期维护「用户自选可读 providerId 作主键」的旧产品合同。
- 为旧 `NOVEL_MASTER_PROVIDER_<SLUG>_API_KEY`（如 `OPENAI`）提供别名或按内置 key 解析旧 env。

## 核心需求

1. **名称即对人身份**：服务商在 Mobile / Desktop 主路径上以非空「服务商名称」出现；用户通过改名称完成「重命名」，不通过改技术主键。
2. **技术主键系统生成**：创建不收集技术主键；主键为 UUID；UI 主路径不展示该 UUID。
3. **名称必填**：创建、编辑、升级后的数据均不得存在空名称；提交空名称必须被拒绝并有明确提示。
4. **连接信息仍必填（按现网）**：创建自定义服务商仍需协议、Base URL 等现网要求的连接字段；API Key 策略与现网一致（可创建时填写或其后补齐，不因本迭代放宽/收紧密钥规则，除非与隐藏 id 冲突时仅做必要适配）。
5. **模型主文案走服务商名称**：默认 `{服务商名称}/{modelName}`；服务商改名后，依赖该公式的展示随之更新。
6. **三端 + CLI 语义一致**：同一套「名称对人、UUID 对内（CLI 列表可暴露 UUID 供脚本，类似模型 list）」；不做旧 slug 兼容，也不做旧 slug 段 env 密钥名兼容。
7. **可靠升级**：已有安装从旧「可读 id 主键」升到新合同后，服务商与下属模型、密钥、选用关系可用，且每条服务商有非空名称。

## 验收标准

### 创建与展示（Mobile / Desktop）

- **Given** 用户打开「添加服务商」  
  **When** 查看表单  
  **Then** 存在必填「服务商名称」（或等价文案），**不存在**需用户填写的 Provider ID / 服务商 ID 输入项；仍可见协议、Base URL 等连接字段  

- **Given** 用户填入非空名称与合法连接信息并保存  
  **When** 创建成功  
  **Then** 进入该服务商详情（导航使用系统返回的服务商 UUID，而非用户输入的技术 id）；成功提示文案使用刚填写的服务商名称；回到列表后主标题为该名称且不是 UUID  

- **Given** 用户将名称清空或只输入空白并尝试保存（创建或编辑）  
  **When** 提交  
  **Then** 保存失败或被拦截，并提示名称必填；编辑不得把名称清成空  

### 编辑与 Agent（Mobile / Desktop）

- **Given** 已存在名称非空的服务商  
  **When** 用户修改名称并保存  
  **Then** 列表、详情标题、Agent 服务商选项中的文案均为新名称  

- **Given** Agent 编辑页选择服务商  
  **When** 打开下拉/选项列表  
  **Then** 选项主文案为服务商名称，而非 UUID  

### 模型主文案

- **Given** 某服务商名称为「智谱」，其下已保存模型 `modelName` 为「快速回复」  
  **When** 用户在模型选择器 / 当前模型 / 等价主展示处查看  
  **Then** 默认主文案为「智谱/快速回复」（或同等「名称/modelName」形态），**不以**服务商 UUID 为前缀  

### 升级

- **Given** 升级前库中存在以可读 id 为主键的服务商（含名称曾为空者）  
  **When** 完成升级进入应用  
  **Then** 每条服务商均有非空名称；其下已保存模型仍可请求；API Key 仍对应该服务商；用户主路径仍只见名称不见 UUID  

### CLI（破坏性新合同）

- **Given** 使用新版 CLI  
  **When** 创建服务商  
  **Then** 须提供非空名称（如 `--name`）；不要求用户提供旧式自选 slug 主键  

- **Given** 编辑已有服务商名称  
  **When** 使用改名旗标（与 create 一致，如 `--name`）传入空或纯空白  
  **Then** 失败（名称不可清空）；成功改名后 list/current 对人输出为新名称  

- **Given** 列出或查看当前服务商  
  **When** 查看对人友好的输出  
  **Then** 以服务商名称为主识别信息；若提供 UUID，仅作为脚本/精确选用用途（类似模型 list 含 UUID），不作为 UI 产品主文案要求  

- **Given** 依赖旧文档 `nm provider create --providerId openai` 或「`--providerId` = 用户自选可读 slug」的脚本  
  **When** 在新合同下运行  
  **Then** **不**要求仍按旧语义成功（本迭代明确不兼容）  

- **Given** 依赖旧 env `NOVEL_MASTER_PROVIDER_OPENAI_API_KEY`（或其它旧 slug 段）注入内置服务商密钥  
  **When** 升级到本迭代后仍使用旧变量名  
  **Then** **不**要求仍命中该服务商密钥（ref 已为 UUID；须改用新 env 名；本迭代不提供旧名别名）  

### 负向 / 回归

- **When** 在 Mobile / Desktop 服务商主路径浏览列表、详情、创建、编辑、Agent 选服务商  
  **Then** 不得以服务商 UUID 作为默认主标题或默认选项文案  

- **When** 使用内置服务商  
  **Then** 用户见到的是友好名称；内置仍不可删、协议仍不可改（与现网产品护栏一致）  

## 约束与依赖

- 依赖并修订：`provider-model`（服务商身份）、`saved-model-identity`（模型主文案前缀）。
- 撤销：`mobile-bugfix` 中「移除服务商展示名称、UI 改展示服务商 ID」相关需求与验收（该迭代其余条目不受影响）。
- CLI 与 env 破坏性变更须在发版说明中写明（本 PRD 验收不要求旧脚本、旧 `NOVEL_MASTER_PROVIDER_<SLUG>_API_KEY` 继续可用）。技术迁移判定、展示函数签名、调用面等见 SPEC。

## 风险与待确认项

- 服务商**名称是否全局唯一**：未强制；若允许重名，CLI/UI 在需精确指定时应以 UUID 消歧（list 可提供 UUID 列）。若产品后续要求唯一，可另开变更。
- 「CLI 列表是否必须打印 UUID 列」与模型 list 对齐即可；以「脚本可精确选用、人对名称」为原则，具体列格式留给实现/SPEC。
- 固定内置 UUID 确定后，发版说明应给出对应 `NOVEL_MASTER_PROVIDER_<UUID>_API_KEY` 示例，避免 CI 误用旧 `OPENAI` 名。
